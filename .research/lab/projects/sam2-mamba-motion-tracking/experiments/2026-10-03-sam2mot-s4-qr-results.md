## 解釈（暫定）

### Q-R の悪化は association 側に集中している

AssA −10.15、IDF1 −10.35、IDSW +710 に対し、DetA は −1.75 にとどまる。悪化の大きい系列は 0065（−42.52）、0019（−28.89）、0041（−21.08）、0034（−13.03）。

### 0065 では、Q-R がなかった衝突を生み出している

dancetrack0065 は 5 人の系列で、S3 では途中追加 0、CoI の衝突 0 で、HOTA 91.23 だった。S4 では Q-R が 1,106 回発動し、途中追加 3、衝突ペア 1,068 が生じて、HOTA は 48.70 まで下がった。全体でも CoI の衝突ペアは 9,195 → 20,918 に増えている。

これは、Q-R が**あるトラックの keyframe を別の人物の box で上書きし、2つのトラックが同じ人物を追うようになった**という経路と整合する。マッチの基準が Addition と同じ IoU > 0.0 なので、少し重なっただけの隣の人物の検出でも条件 (2) を満たしてしまう。conditioning frame は SAM2 の既定（`max_cond_frames_in_attn=-1`）で以降の全フレームから参照され続けるため、誤った keyframe の影響が系列の最後まで残る。ただし、個々の発動のマッチ IoU は記録していないため、この経路はまだ直接確認していない。

### 発動頻度と速度

Q-R は 42,464 回発動し、conditioning frame が溜まり続けるため、推論は 2.4 倍遅くなり、VRAM は最大 22.51 GiB まで増えた。論文の Limitation（推論速度）とは方向が一致するが、論文がここまで頻繁に keyframe を更新しているかは記載がない。

## 次の判断（ユーザー決定事項）

切り分けの候補（いずれも config フラグの切替だけで、コード変更は不要。各 run は GPU 0 で約 3〜7 h）:

1. **マッチの基準**: `--qr-match-iou-thr 0.5` などで、隣の人物とのマッチを除く。上の経路が正しければ最も効くはず
2. **発動頻度**: `--qr-min-interval` で同一トラックの更新間隔を空ける
3. **A5 の操作**: `--qr-as-refinement` で、conditioning frame ではなく非 conditioning の補正にする（誤った keyframe が残り続けない）

このほか、spec に残っている作業:

- DanceTrack test への提出（発動条件は成立済み）
- spec の機構署名「DetA ほぼ不変」の見直し

## 追記（2026-10-08）: A5 の切り分け（Q-R を補正として入れる）

マッチ閾値の問題ではなかったため、A5（keyframe 更新の操作）を切り替えた run を取った。マッチした検出 box を、conditioning frame ではなく非 conditioning の補正として入れる（`--qr-as-refinement`）。それ以外は S4 本番と同一。`results/tracks/s4_qr_refine/`、25/25 成功、形式検証 PASS、3.39 h、peak VRAM 12.03 GiB。

| | HOTA | DetA | AssA | MOTA | IDF1 | IDSW | FN | FP |
|---|---|---|---|---|---|---|---|---|
| S3（A6 のみ） | 68.22 | 72.26 | 64.57 | 76.88 | 75.42 | 839 | 22366 | 28856 |
| S4（A5: conditioning frame、本番） | 61.85 | 70.51 | 54.42 | 73.85 | 65.07 | 1549 | 23565 | 33751 |
| **S4（A5: 補正）** | **69.25** | 72.49 | 66.31 | 77.20 | 77.23 | 845 | 21473 | 29010 |
| Δ 補正 − S3 | **+1.03** | +0.23 | +1.75 | +0.33 | +1.80 | +6 | −893 | +154 |

- **Q-R を補正として入れると、S3 から HOTA +1.03、AssA +1.75、IDF1 +1.80 と改善した**。論文 Table 3 の Q-R の寄与（HOTA +1.7 / MOTA +1.8 / IDF1 +2.5）と同じ向きで、大きさも近い
- 25系列中 17 系列で HOTA が上がった。S4 本番で大きく崩れた系列も S3 の水準に戻った（0065: 48.70 → 91.07、0019: 32.07 → 66.71、0041: 26.47 → 44.40）
- Q-R の発動は 42,464 → 23,066 回、推論時間は 7.07 → 3.39 h、peak VRAM は 22.51 → 12.03 GiB に下がった
- したがって、**S4 の悪化の原因は A5 の第一候補（box prompt を conditioning frame として追加）だった**。conditioning frame は SAM2 の既定設定で以降の全フレームから参照され続け、Q-R が頻繁に発動すると、その都度の box が keyframe として積み重なる。補正として入れると、そのフレームの出力だけが修正され、通常のメモリ（直近数フレーム）を通して以降に効く
- 論文の "updates the object's keyframe information" を「conditioning frame を追加する」と読んだ spec の解釈が外れていた可能性が高い
