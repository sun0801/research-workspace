# 学習済みV3のMambaのstateは、何ステップ残るか（重みの読み取り、CPU）

11/13 MTG の宿題「stateの持ち方（シリアルか並列か）を場所ごとに検討する」の判断材料として、学習済みの重みから、Mamba の state が1ステップでどれだけ減るかを読んだ。学習・推論はしていない。GPU は使っていない。SAM2 repo は読み取りだけ。

スクリプトと出力：[figures/2026-11-17-mamba-state-time-constants/](figures/2026-11-17-mamba-state-time-constants/)（`state_decay.py`、`data/state_decay.txt`）。図はない。

検討の全体は [brainstorm メモ](../../../secretary/notes/brainstorm/2026-11-17-state-design-serial-vs-parallel.md)。

## 結論

- **学習済みの V3・A-b の時定数（A と dt の bias）は、初期値の分布からほとんど動いていない。** `A_log` と初期値（log 1〜16）の差は平均 0.003〜0.013、最大 0.10。2 epoch から 22 epoch の間の変化は、`A_log` 0.8%、`dt_proj.bias` 0.6%（V3 の64段。同じ間に `in_proj`・`x_proj`・`out_proj` は 63〜71%、`dt_proj.weight` は 33% 動いている）。
- **state の半減期は、中央値で約11ステップ。** 10% 点 1.3、90% 点 約75、最大 約700 ステップ（64段、V3）。128段・256段、A-b もほぼ同じ。
- **並列（マスごと）では、1ステップ＝1フレーム。** 半減期の中央値は約11フレーム。学習の区間（8フレーム）の終わりで、state の成分の 56% が半分以上残る。
- **シリアル（マスを順に読む）では、1ステップ＝1マス。** 同じ時定数のままなら、64段の1フレーム分（4,096マス）先に残るのは最大でも 2%、平均 0.01%。1行（64マス）先でも、半分以上残る成分は 12%。

## 方法

- Mamba の state の更新は h ← exp(−dt·|A|)·h ＋（入力の項）。1ステップで残る割合は exp(−dt·|A|)、k ステップで exp(−k·dt·|A|)。
- `A = −exp(A_log)`（[d_inner, 16]）、`dt = softplus(dt_proj.bias)`（[d_inner]）で計算した。
- **dt のうち入力に依存する分（`dt_proj.weight` × 入力から作る値）は入れていない。** 実際の dt は入力ごとに、ここでの値より大きくも小さくもなる。
- 初期値の参照は、`mamba_ssm/modules/mamba_simple.py` の既定（dt は 0.001〜0.1 の対数一様、A は 1〜16）を乱数で作った（seed 0）。

## 読み取り

- 並列の V3 は、重みの上では、数フレームから数十フレームの記憶を持てる時定数になっている。11/6 までの評価で state の寄与が0付近だったことは、「state がすぐ消えるから」では説明できない（bias だけの値での話）。
- 画面全体をシリアルに読んで state を次のフレームへ渡す形（10/18 の V4）は、今の初期値と学習の進み方のままだと、前のフレームの情報がほとんど届かない。届かせるには、dt を2桁ほど小さくする初期値にするか、入力に依存する分で dt を0近くまで下げることを学習する必要がある。
- 物体の領域だけ（数十〜数百マス）や、縮めた画面（16×16）なら、遅い成分の一部が前のフレームまで届く。

## 限界

- 入力に依存する dt を入れていない。`dt_proj.weight` は学習で 33% 動いているので、実際の残り方は違う可能性がある。確かめるには、val の動画で dt の実際の値を記録する（推論だけ。GPU が要る）。
- 1ステップで残る割合は、state に書いた情報が出力に効く長さの上限の目安で、実際に使われているかは別の問題。
- シリアルの値は、並列で学習した重み・初期値の時定数をそのまま当てはめた計算。シリアルで学習したモデルの値ではない。
- 2つの重みはどちらも単一 seed。

## 追記 2026-11-17 16:45（A_log が動かない原因の切り分け、実際の dt、出力のうち持ち越した state の割合）

ユーザーの依頼（11/17）：A_log が初期値からほぼ動いていない件の原因を調べる。外部リポジトリは編集しない。GPU は短い確認に使ってよい。

### 結論

- **「0.8%」は、値の大きさ（A_log は約2）で割った見かけの小ささ。** Adam の1歩の大きさで測ると、A_log の動きは他のパラメータと同じ程度（下の表の「Δ / √Σlr²」0.63。in_proj 0.88、x_proj 0.71）。どのパラメータも、2→22 epoch の間は向きのそろわない酔歩に近い動き方をしている。
- **学習率・重み減衰・グループ分けは原因ではない。** A_log は adapter の学習率（3e-4 → 3e-5 の cosine）のグループにあり、重み減衰は 0（公式実装の `_no_weight_decay` と同じ扱い）。学習率の合計 Σlr は 4.07 で、時定数を2倍にするのに要る動き（A_log で 0.69）を十分に出せる。
- **原因は、時定数を動かす向きの勾配が、そろって出ていないこと。** 学習用の8フレームの区間 64個で、勾配の向きのそろい方は、学習の初め（2 epoch）も終わり（22 epoch）も、Mamba のパラメータはすべて「区間ごとにばらばら」の水準（0.09〜0.23、64段の A_log は 0.13・0.14。ばらばらなら 1/√64＝0.125 前後）。
  - 8フレームの区間の中では、Mamba の出力のうち、前のフレームから持ち越した state から来る分は、64段で 2.5% 以下（下の dt の計測）。時定数を変えても、損失はほとんど変わらない。
- **さらに、遅い成分ほど、Adam の eps で更新が弱められている。** A_log の勾配は、その成分の速さ（dt·|A|）にほぼ比例する（相関 +0.81）。半減期が長い成分は勾配が小さく、勾配の2乗平均の平方根が Adam の eps（1e-8）を下回る。更新の大きさは、半減期 8〜32 ステップの成分で本来の 37%、32〜128 で 11%、128 以上で 2%（64段）。256段では A_log の 93% が eps を下回る。
  - 勾配の全体の大きさを 0.1 に切りそろえる設定（SAM2 公式の学習設定）で、勾配は中央値で約 1/17 に縮められてから Adam に入る。全体の大きさの 40〜55% を、256段の出力層の bias（32個）が占めている。
  - 時定数を学習で長くしたい場合、いちばん効いてほしい遅い成分ほど動きにくい、という向きの偏り。
- **dt の入力による変化も小さい。** 実際の dt は、bias だけの値の 0.65〜1.6 倍（64段、10〜90% 点）。128段 0.87〜1.14 倍、256段 0.96〜1.04 倍。state の残り方と半減期（中央値 10.6 ステップ）は、bias だけの値とほとんど同じ。Mamba の「選択的」な時定数は、ほぼ使われていない。
- **state の寄与がほぼ0だったこととの関係（私の読み）。** どちらも「8フレームの学習では、持ち越した state が損失にほとんど効かない」ことの表れと見ている。A_log が動かないことは、寄与が0の原因というより、同じ原因から出た結果。
- **学習と推論で、state の効き方がずれている。** 推論（長い動画）では、持ち越した state から来る分が、64段で 13%、128段で 35% まで育つ（64フレーム以上持ち越したとき）。学習は8フレームまでなので、この大きさの state は学習で見ていない。
- **Mamba では普通か。** 公式実装は A_log・D・dt の bias を重み減衰から外すだけで、学習率を別にする・A を固定するなどの扱いはない（`mamba_simple.py` 109〜115行、`mamba2.py` 130〜140行）。Mamba の論文は、言語モデルで A の初期値を変えても差が小さい（Table 8：実数の初期値で perplexity 8.71〜8.85）、選択的なパラメータの中では Δ が最も効く（Table 7）、と報告している。学習後の A が初期値から動くかどうかを調べた報告は、今回は確かめられていない（下の「確認できなかったこと」）。

### 方法

すべて SAM2 repo は読み取りだけ（import のみ）。スクリプトは `figures/2026-11-17-mamba-state-time-constants/`。

- Mamba の出力の内訳は、adapter の中（out_proj の後）の比。α·W_out を通って特徴にどれだけ足されるか、マスクにどれだけ効くかは測っていない。

- A-b（A_corr）では、勾配と dt を測っていない（時定数の読み取りだけ。本文の表）。
- eps を小さくする・A_log の学習率を上げる、などで時定数が動くか、動いたら state の寄与が増えるかは、試していない（学習が要る）。
