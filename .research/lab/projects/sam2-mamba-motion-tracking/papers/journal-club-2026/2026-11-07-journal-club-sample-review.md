## 指摘（重要度順）

### 高

**1. 問いが2本に当てはまらない（1・2・39枚目）**
- 問題: 「Mamba の state を何に紐付けるか」と問うているが、フレームをまたいで SSM の state を持ち越すのは TV3S だけ。TS-Mamba は毎フレーム過去の token を集めて scan する。MaD の Mamba2 は8フレームの窓で毎時刻作り直す（39枚目の「発表者の整理」に自分で書いている）。これでは「問いは立てたが、答えたのは1本だけ」に聞こえる。2枚目の背景「固定サイズの state に圧縮し、1フレームあたり一定のコストで更新」も TV3S にしか当てはまらない。
- 直し方: 問いの主語を state から「過去」に変える。
  - タイトル案: 「動画の Mamba は、過去を何に沿って集め、どこまで信じるか」
  - 2枚目の問いを2軸に分ける。① 過去を何に沿って集めるか（位置・軌跡・物体）、② 集めた過去をどこまで信じるか（無条件・類似度で選ぶ・信頼度で 0/1）
  - 2枚目の背景の2行目を差し替える: 「Mamba（SSM）は系列を固定サイズの state に圧縮して読む。動画では、どの過去をどの順で読ませるかを設計する必要がある」

**2. TS-Mamba → MaD のつなぎに飛躍がある（29枚目）**
- 問題: 「物体単位で未来を予測するなら、予測をどこまで信じるか？」は、予測をしない TS-Mamba の中身からは出てこない。
- 直し方: TS-Mamba の限界（軌跡を無条件に信じ、タイヤの回転で崩れる）からつなぐ。
  - 案: 「次論文：集めた過去が外れていたら？ TS-Mamba は軌跡を無条件に信じる → 外れたときは使わない仕組み（Memory as Dynamics）」
  - 19枚目のつなぎでも、TS-Mamba が state を持ち越さないことを先に伝えておく: 「次論文：位置に固定せず、動きに沿って過去を集め直したら？（state は持ち越さず、毎フレーム集め直す）→ TS-Mamba」

**3. 39枚目のまとめが言い過ぎ**
- 「② 予測をどこまで信じるか（きっぱり止める方がよい）」の根拠は、MaD の ablation 1つ（Table 14: 0/1 の gate 74.5 vs soft gate 72.3）だけ。データセットは LaSOT、モデルは B サイズのみ。soft gate が劣る理由（重みが 0.2〜0.8 に残り、誤差が memory に入り続ける）は著者の解釈で、memory の汚染を測ったわけではない。
  → 「MaD（LaSOT）では、0/1 の gate が学習した soft gate を上回った（74.5 vs 72.3）。他の条件では検証されていない」
- 「① 位置 → 軌跡 → 物体」の矢印は、タスクも評価も違う3本を進歩の順のように見せている。
  → 矢印をやめて「位置／軌跡／物体」と並べ、「タスクが違うので優劣は比べられない」と添える。
- 表の TV3S の「信じる仕組み：Mamba の選択（入力依存）」は、どの Mamba にもある性質で、TV3S 固有の仕組みではない。
  → 「なし（全フレームを無条件に state に入れる）」に。こうすると「無条件 → 類似度で選ぶ → 信頼度で 0/1」の流れがはっきりする。
- 表の MambaOut 行はセルがすべて「—」。比較の軸に乗らない論文を、ほかと同じ形の行に入れている（先生の指摘3）。
  → 表から外し、表の上に「前提（MambaOut）：SSM が要るのは長く causal な系列」と1行で置く。

**4. MambaOut の「要るか」が後で回収されない（8・19・29・38・39枚目）**
- 問題: 冒頭で「Mamba は要るか」と問うたのに、後の3本で Mamba を別の部品に替えた比較を一度も見せていない。さらに39枚目では「後半2本は SSM を短い系列に使う」と書いており、MambaOut の基準（L > 6D）に照らすと Mamba が要らない側に入ってしまう。先生が真っ先に突きそうな点。
- 直し方: 各論文のまとめに「Mamba を他に替えた比較」を1行足し、39枚目の表にも同じ列を足す。
  - TV3S: なし（Table 3〜6 で変えているのは shift・window・block 数・フレーム数）
  - TS-Mamba: 付録 Table 4 で、TSMA を deformable 系（DCN / FGDA / DA / FDA）に替えて比べている。PSNR は 30.59〜30.69 dB に対して 30.73 dB（+0.04〜0.14 dB）、MACs は 132〜148G に対して 112G
  - MaD: なし（24層の Mamba2 を他の系列モデルに替えた比較はない。入力は8フレーム分）

**5. 32枚目「memory の更新は観測ベースのまま」は不正確**
- 原典は Sec. 3.1 で「memory 更新 U は観測ベースのまま」と書く一方、Sec. 3.5 では「ρ_t = 1 のとき、予測の prompt が decode に加わり、その結果 SAM2 の memory が更新する内部 state に影響する」と書いている。Fig. 6 の caption にも「小さい r でも、誤った予測が少しずつ memory に入る」とある。つまり、更新の仕組み自体は変えていないが、予測を使ったフレームでは予測の影響を受けた出力が memory に入る。今の書き方では、31枚目の「誤った予測が memory に入り」とも矛盾して見える。
- 直し方: 「予測は memory に直接は書き込まず、decoder の prompt に足すだけ。ただし予測を使ったフレーム（ρ = 1）では、その出力が memory に入る（Sec. 3.5）」。この経路はまさに汚染の経路なので、本研究につなぐ材料にもなる。

**6. MaD の ablation で比較の基準が見えない（32・36・37枚目）**
- 問題: 「HiM2SAM の memory 更新を下敷きにしている」ことが、36枚目の結果で初めて出てくる。原典 Sec. 4.1 には「特に断らない限り、全実験この構成」とある。つまり37枚目の 70.5 / 72.3 / 74.5 はすべて HiM2SAM 方式の上で測った値で、66.0（素の SAM2.1-B）との差には HiM2SAM 方式の効果も混ざっている。同じ構成で予測を使わない行は、論文にない。
- 直し方:
  - 32枚目の冒頭に構成の前提を書く（先生の指摘2）: 「SAM2.1 は凍結し、memory 更新には HiM2SAM の方式を使う。その上に RPM を足す」
  - 37枚目の表に参考行「HiM2SAM-B（予測なし、Table 1）73.4」を足す。タイトル案: 「Ablation：予測を毎フレーム使うと 70.5 で、予測なしの HiM2SAM-B（73.4）にも届かない。信頼度で選ぶと 74.5」。構成が完全に同じ比較ではない、と添える。
  - 38枚目の「『無条件の予測は予測なしより悪い』を直接示す数値はない」は、この参考値を見せたうえで残す。

**7. 18枚目のタイトルが本文と矛盾している**

**10. TS-Mamba の説明と主張の強さ（21・27・28枚目）**
- 21枚目「計算量の制約で、直前1フレームしか使わない」: 原典の言い方（Sec. 1、Sec. 2.2「特徴の位置合わせは直前1フレームに基づく」）には沿っている。ただ、比較手法の FDAN・TMP などは前フレームの特徴を伝播させる方式なので、古い過去も間接的に運んでいる。
  → 「位置合わせに使うのは直前1フレームだけ。それより古い過去は、伝播する特徴に間接的に残るだけ」。こう書くと「state で持ち越す（TV3S・従来の VSR）vs 過去を集め直す（TS-Mamba）」の対比がはっきりし、論文間のつなぎも強くなる。比較手法がどう伝播しているかは、それぞれの原典で確かめてから書く。

  → 右側の注記を「計算量（112 → 84G）と params（3.0 → 1.7M）も同時に減る。位置を固定したまま集める比較はない」に。
- 28枚目のタイトル「オンライン手法の中で PSNR が最も高く、MACs は最小」: REDS4 での FDAN との差は 0.02 dB で、Vid4（BD）では FDAN が上。著者の主張の中心も効率にある。

## 質疑で聞かれそうな質問

1. 「MambaOut の基準だと、後半2本の SSM は短い系列に使っている。Mamba である必要はあるのか」
   - 方針: 検証が薄いことを認める。TS-Mamba は付録 Table 4 で TSMA を deformable 系に替えて比べており、差は +0.04〜0.14 dB、MACs も少ない。MaD には Mamba2 を他に替えた比較がない（8フレーム分の入力に24層）。TV3S にもない。「3本とも、Mamba が要るかを主な問いにはしていない」と答える。

2. 「MaD の 66.0 → 74.5 のうち、RPM の効果はどれだけか。比較は公平か」
   - 方針: 全実験が HiM2SAM の memory 更新の上で行われていると先に言う。RPM の上乗せの目安は HiM2SAM-B との差（LaSOT 73.4 → 74.5、LaSOT_ext 59.3 → 60.9）。比較相手の SAMURAI や HiM2SAM などは学習しない手法だが、MaD は RPM を VOS データで学習しており、params も 81M → 93M に増える。GOT-10k の SR0.5 では SAMURAI が上。同じ構成で予測を使わない行がないことも言っておく。

3. 「TV3S は、state を持ち越すことの効果を示せているのか」
   - 方針: 直接は示していない。Table 6 は、同じ学習済みモデルで推論時の過去フレーム数を変えただけで、state なしで学習し直した比較はない。評価も、32フレーム未満の動画と最初の32フレームを除いた別の条件。mIoU は8フレームで頭打ち（39.7）、mVC16 は 79.1 → 87.8。学習は4フレーム、推論は動画全体と、系列長も違う。

4. 「TS-Mamba の軌跡は本当に効いているのか。差は誤差ではないか」
   - 方針: w/o Trajectory（−0.28 dB）は flow を使う軌跡の生成と token 選択を同時に外していて、params（3.0 → 1.7M）と MACs（112 → 84G）も同時に変わる。軌跡の loss だけを外したときの差は −0.03 dB。位置を固定したまま集める比較はない。REDS4 での FDAN との差は 0.02 dB で、主張の中心は MACs の削減だと答える。

5. 「本研究（hidden state contamination）とどうつながるのか」
   - 方針: 直接の先行研究ではないと先に言う。MaD の「汚染」は SAM2 の memory bank の汚染で、MaD は SSM の state を持ち越さない。ただ、汚染の経路（ρ = 1 のとき、予測の影響が decoder 経由で memory に入る。Sec. 3.5）と、「連続的な重みでは誤差が残り続ける」という説明（Table 15、著者の解釈）は、本研究で state 更新の gate を考える材料になる。state を位置に固定して持ち越すという点では、TV3S が本研究の V3 と同じ形をしている。物体が動くと、その位置の state に別の物体の情報が混ざる。これを本研究の問いの具体例として話す。
