## 0. 先に結論

1. **「平行移動のみ」は、11/12 の制約案と同じものではない。より強い制約。** 制約案は「隣と1マス以内でそろえる」滑らかさの制約で、回転・拡大・変形を許す。「平行移動のみ」は「ある範囲の中は同じ移動」。制約案の許容を0にして範囲を広げた極限に当たる（1.）。
2. **運動を ①平行移動 ②アフィン ③非剛体 に分けると、MOSE の1フレーム差では ① が大半。ただし速い物体では足りない。** RAFT を参照にした事前確認で、物体ごとに1つの平行移動から1マスより離れるマスは全体 14%・速い層 28%。1フレームあたりの回転は平均 2.6°、拡大縮小は 4% と小さい（2.）。
3. **基準案は「局所ブロックごとの平行移動」を推す。物体ごとは参照にとどめる。** ブロックの中で類似度を足してから移動を選ぶ。マスクを使わないので、マスクの外の扱いという問題が起きない。ブロックの大きさは学習なしの診断で決める（4.）。
4. **差し替え口は「基準の移動＋直し」の2段にする。** 基準案が出す移動を、次の段（許容つき・学習）が直す形。基準案は捨てずに、学習で直す案の出発点になる（3.）。
5. **学習ベースの本命候補は、11/12 の「学習で直す案」を直したもの。** 0 からではなく基準案の移動から始め、畳み込みで隣を見ながら残りを直す。11/12 の本命1（周りごと照合）は、運動の種類で見ると「3×3 のブロックの平行移動の学習版」で、非線形な動きへの拡張にはなっていない（5.）。
6. **事前確認が示す学習版の役割は、「回転に対応する」より「小さい範囲でも移動を決められるようにする」「部分の境界・遮蔽を扱う」の方。** 小さいブロックなら ②③ もほぼ平行移動で近似できるが、小さいブロックでは似たマスが多くて移動が決まらない。この両立が学習版の仕事になる（2.・5.）。

## 1. 「平行移動のみ」と 11/12 の制約案の関係

**記録の確認**

- 11/13 の資料に載せた制約案：「上下左右の隣が選んだ移動と、1マス以内でそろう候補の点数を上げて選び直す。数回くり返す。物体の境界ではそろえない」。11/12 メモでは、「同じ移動」まで要求しない理由を「回転・拡大・変形を禁止してしまうから」と書いている。
- 11/13 の MTG：ユーザー「隣のピクセルとの位置関係を保ったまま動く」。先生「回転などがあれば位置関係は変わる。それでも対応を取るのが一般の位置合わせ。ここでいうのは平行移動のみの位置合わせか」。ユーザー「制約を入れる案は平行移動のみ」。決定事項も「隣のマスとの位置関係を保つ（平行移動のみの）対応付けから実装する」。

**整理**

各マスの移動を u(p)（t のマス p が t−1 のどこから持ってくるか）とする。

| 方式 | 隣どうしの移動の関係 | 決める値の数 | 回転・拡大・変形 |
|---|---|---|---|
| 今の A-b | 制約なし | マスごとに自由 | 許す（並びは崩れる） |
| 11/12 の制約案 | 隣との差が1マス以内になるよう点数を上げる | マスごと（ゆるくつながる） | 許す |
| 平行移動のみ（ブロックごと） | ブロックの中は同じ移動 | ブロックごとに2つ | ブロックの中では許さない |
| 平行移動のみ（物体ごと） | 物体の中は同じ移動 | 物体ごとに2つ | 許さない |

- 制約案の「1マス以内」は、隣どうしの移動の差を1マスまで許す。回転なら1フレームに約1ラジアン、拡大なら2倍まで許すことになり、実質どんな動きも禁止しない。**滑らかさの制約であって、平行移動の制約ではない。**
- MTG で先生と確認した「平行移動のみ」は、言葉どおりなら下の2行。**資料に書いた案（滑らかさ）と、口頭で合意した案（平行移動のみ）は、強さが違う。**
- 2つは別物ではなく、同じ軸の上にある。制約案の許容を0にし、そろえる範囲を広げると、その範囲の中は同じ移動になる。逆に、平行移動のみの案に「基準の移動から ±1 マスの中で選び直してよい」を足すと、制約案に近づく。
- したがって、11/12 の制約案は捨てない。**「平行移動のみ」の次の段（許容つきの案）として、学習なしで非線形な動きへ広げる道**に置き直す（3. の表）。

## 2. 対応したい運動の分類と、データでの内訳

| | 運動 | 移動場の形 | 例 |
|---|---|---|---|
| ① | 平行移動 | 範囲の中で同じ移動 | 横に走る車、カメラの平行な動き |
| ② | 回転・拡大縮小（アフィン） | 位置の1次式。物体の中心から離れるほど移動が変わる | 近づく・遠ざかる物体、向きを変える物体 |
| ③ | 部分ごとに違う動き（非剛体） | 部分ごとに別の移動。部分の境で不連続 | 人・動物の手足、関節のある物体 |

（画像の位置合わせでいう 剛体 → アフィン → 非剛体 の分け方と同じ。先生の「回転などがあっても対応を取るのが一般の位置合わせ」は ②③ を指す。）

**事前確認（今日、CPU だけ）**：11/12 に保存した RAFT の移動場を、物体ごとに ①→② の順に当てはめた。[実験ログ](../../../lab/projects/sam2-mamba-motion-tracking/experiments/2026-11-16-translation-only-precheck.md)。MOSE tuning 125動画、1フレーム差、64×64 マス。

| 物体のマスのうち（閾値1マス、20マス以上の271物体） | 遅い | 中くらい | 速い | 全体 |
|---|---|---|---|---|
| ① 1つの平行移動で合う | 97% | 87% | 69% | 83% |
| ② アフィン変換なら合う | 2% | 8% | 16% | 9% |
| ③ どちらでも合わない | 1% | 5% | 15% | 8% |

- 閾値を 0.5 マスにすると、全体で 69%・15%・16%、速い層で 49%・22%・29%。
- 1フレームあたりの回転は平均 2.6°（速い 3.8°）、拡大縮小は 4%（速い 7%）。物体の端から端で作る移動の差は平均 1.1 マス（速い 1.9 マス）。
- 範囲を小さくすると、平行移動だけで合う。周りのブロックの中央値から1マスより離れるマスは、3×3 で 2%、5×5 で 3%、9×9 で 5%、15×15 で 8%、物体全体で 14%（速い層は 4%・7%・10%・15%・28%）。

**読み取り**

- ①だけで済むのは遅い物体。**速い物体（A-b で差が出てほしい層）では、物体ごとの平行移動は3割のマスで1マス以上外す。** ②③ に広げる必要がある、というユーザーの見立てと合う。
- 一方で、**②は1フレームでは小さい**。9×9 のブロックの端でも、回転 2.6° が作るずれは約 0.2 マス、拡大縮小 4% で約 0.2 マス（速い層で約 0.3 マス）。小さいブロックの平行移動で、②と、③の「部分の内側」はほぼ近似できる。
- 残るのは、③の部分の境と、物体の境界・遮蔽。そして下の「決めにくさ」。
- **ブロックの大きさには綱引きがある。** 小さいほど ②③ に合うが、似たマスが多い所では移動が決まらない（11/13 の資料の1マスの例では、3×3 の類似度を平均しても RAFT の移動先に重みが移らなかった）。大きいほど決まるが、②③ から外れる。**非線形な動きへの対応とは、この綱引きをどう解くか**、と言い換えられる。
- 注意：RAFT は正解ではなく、滑らかな場を出すので ③ を小さく見積もる可能性がある。「どちらでも合わない」には RAFT の誤りも入る。1フレーム差だけの値。

## 3. 差し替え口の設計（拡張できる形）

**今の実装（読み取りで確認）**：`CorrespondencePyramidAdapter._corr_weights` が、類似度の表 C（`local_similarity`、[B, 225, 64, 64]）→ `correspondence_weights(C, method)` → 重み W（[B, 225, 64, 64]）を作り、`transport_tokens` が W で state を運ぶ。W は画像エンコーダの特徴だけで決まり、物体によらない。11/12 に「差し替え口の出力は W で統一する」と決めている。

**提案：W を作る部分を2段に分けて考える**（既存のコードは変えず、`corr_method` に方式を足すだけで実現する）

1. **移動を決める段**：C（＋現フレームの特徴）→ 各マスの移動 u(p)（小数）と信頼度 c(p)。
   - 基準の移動 u₀ を出す部分と、それを直す部分 Δu に分ける。u = u₀ ＋ Δu。
2. **W を作る段**：u（と c、C）→ W。行き先の周り4マスの双線形補間、最も近い1マス、行き先の ±1 マスの中で類似度の softmax、の3通りを同じ口で選べる。

| 段 | 方式 | u₀（基準の移動） | Δu（直し） | ① | ② | ③ | 学習 |
|---|---|---|---|---|---|---|---|
| 現行 | A-b（softmax） | ― | マスごとに自由 | 並びが崩れる | | | なし |
| **基準案** | ブロックの平行移動 | ブロックで類似度を足して選ぶ | 0 | ○ | △ ブロックの中で近似 | △ 部分の内側は近似、境は× | なし |
| 許容つきの案 | 基準案＋11/12 の制約案 | 同上 | ±1 マスの中で選び直す（隣とそろえる点数つき） | ○ | ○ | △〜○ | なし |
| **学習で直す案** | 基準案＋小さなネットワーク | 同上 | 畳み込みで隣を見ながら直す | ○ | ○ | ○（学習次第） | あり |
| 参照 | 物体ごとに1つ | 正解マスクの中で足して選ぶ | 0 | ○ | × | × | なし |
| 参照 | A-a（DIS・RAFT） | 画像の flow | 0 | | | | ― |

**この形にする理由**

- **基準案を捨てずに使える。** 学習で直す案は、基準案の移動を出発点にする。直しの最後の層を0で始めれば、学習前は基準案と完全に一致する。11/2 サーベイの「flow を基準の offset にした DCN は動くが、基準なしの offset の学習は崩れる」（BasicVSR++ の 32.39 dB と 27.44 dB）と同じ考え方。
- **入れ子になる。** ブロックの大きさ1・小数なしの基準案は、今の argmax と一致する。直しを0にすれば基準案。11/12 の「類似度最大 → 制約 → 本命」の3段は、「A-b → 基準案 → 許容つき → 学習」の4段として1本の軸に並ぶ。
- **下流を変えない。** 出力は W のまま。`transport_tokens`、Mamba、推論時の差し替え（identity・shuffle・diag）、W の統計の記録はそのまま使える。
- **W は物体によらないまま。** フレームの組に1回計算すれば、全物体で使い回せる。

**学習の入れ方（今の制約との関係）**

- 対応付けの部品は Mamba と分けて先に学習し、固定してから Mamba を学習する（W に勾配を流さない今の設計は変えない）。11/12 の本命1と同じ2段の学習。
- 学習パラメータが増えるので、「パラメータは V3 と同じ」は成り立たなくなる。代わりに「学習前は基準案と一致する」を保つ。

## 4. 基準案：ブロックの平行移動（学習なし）

### 4.1 どの範囲で平行移動を推定するか

| | 物体ごと（前フレームのマスク） | 局所ブロックごと（マスクなし） |
|---|---|---|
| 運動への当てはまり（2. の値） | 1マス超が 14%（速い 28%） | 3×3 で 2%、9×9 で 5%（速い 4%・10%） |
| 外形 | 最良の平行移動でも IoU 0.70〜0.73（A-b 0.76） | 未計測（多数決の代用では 0.72〜0.65） |
| 決めやすさ | 物体全体（境界を含む）で足すので決まりやすい | 小さいブロックは決まらない恐れ（3×3 の1例） |
| マスクが要るか | 要る。Mamba はデコーダの前にあるので、前フレームの予測マスクを adapter に戻す配線が新しく要る。マスクの誤りが対応の誤りになる | 要らない |
| マスクの外 | 別に決める必要がある | 区別がない（背景も同じ式） |
| W を物体で共有 | できない | できる |
| 非線形な動きへの拡張 | 物体ごとのアフィン → 部分ごと、と作り込みが要る | ブロックを小さくする・直しを足す、で連続的に広がる |

**推し：局所ブロックごと（1マスずつずらす窓）。物体ごとは、正解マスクを使う参照（範囲が分かっているときの目安）としてだけ測る。**

- 理由は、(1) 速い物体で物体ごとの平行移動は当てはまらない、(2) マスクの配線とマスクの外の場合分けが要らず「簡単に作れる最初の一歩」に合う、(3) 3. の拡張の軸にそのまま乗る、の3つ。
- 反対の材料：小さいブロックで移動が決まるかは未確認（4.5 の診断で確かめる）。決まらない場合は、ブロックを大きくするか、境界を含む物体ごとに寄せるかの判断に戻る。
- ブロックは重ならないタイルではなく、各マスを中心にした窓にする。タイルだと、タイルの境で移動が切れる。

### 4.2 推定の方法

- **類似度を足してから選ぶ**：S(p, d) = p を中心とする k×k のマス p' の C(p', d) の平均（画面の外は除く）。d*(p) = S(p, ·) が最大の d。
  - 各マスが別々に選んだ結果を多数決するのではなく、選ぶ前の類似度（証拠）を足す。1マスでは決まらない所でも、足せば山が立つ、という古典の考え方（ブロックマッチング、コストの集約）。
  - k = 1 で今の argmax と一致する。
  - 追加の計算は、225 枚の 64×64 の地図に k×k の平均をかけるだけ（累積和を使えば k によらず約 100万回の足し算。類似度の計算 約2.4億回に比べて小さい。見積もりで、時間は未計測）。
- **1マス未満**：(a) 整数のまま、(b) 山の頂点とその隣の値に放物線を当てて小数にする（決める値がない）、の2つを比べる。小数のときは行き先の周り4マスの双線形補間で運ぶ。u = 0 なら今の V3 と完全に一致する。
  - くり返しの双線形補間で state がぼやける恐れ（11/2 サーベイ 4.2）があるので、(a) を残す。
- **k**：1・3・5・9・15・画面全体（カメラの動きだけ）を診断で比べて決める（4.5）。根拠の出し方は「RAFT を参照にした当てはまり（小さいほど良い）」と「決めやすさ（大きいほど良い）」の両方が見える指標で選ぶ。
- **事前確認での見込み**：A-b の各マスの移動を物体の中で多数決するだけでも、RAFT との差は 1.07 マス（遅い 0.37・中くらい 0.84・速い 2.02）で、A-b（1.54）・動かさない場合（1.58、遅い 0.46）を全層で下回った。類似度を足す方式はこれ以上を期待するが、未計測。

### 4.3 マスクの外・境界・遮蔽の扱い

- **マスクの外**：ブロックごとなら特別扱いしない。背景も同じ式で、背景の動き（カメラの動き）に沿って運ばれる。
- **物体の境界**：ブロックが物体と背景をまたぐと、2つの動きの証拠が混ざる。基準案では何もせず、境界から1マス以内とそれ以外で分けて測る。
  - 変種として、現フレームの特徴が似ているマスだけを足す重み付き（11/12 の制約案の a(p, p') と同じ考え）を診断に入れる。決める値が1つ増えるので、基準案には入れず、効くと分かった場合だけ採る。
- **遮蔽・物体が去った背景**：正しい持ってくる元がないマス。基準案では何もしない。行き先の類似度 C(p, u(p)) と、そのマスの最大の類似度の差を「信頼度」として記録するだけにする。信頼度が低いマスを「動かさない」「今の A-b の softmax に戻す」は、許容つきの案の側で比べる。「state を消す」は、sinkhorn が保持率 0.68 で失敗しているので、最初は入れない。
- **画面の端**：行き先が画面の外に出る場合は、画面の中に収まるよう移動を切り詰める（行の和を1に保つ）。

### 4.4 基準案の弱点（先に書いておく）

- **外形は A-b より崩れる見込み。** 物体ごとの平行移動では、最良でも IoU 0.73（A-b 0.76）。A-b の長所（どの物体から持ってくるかは当てる）を、基準案は一部手放す。これは基準として記録し、次の段（行き先の ±1 マスの中で類似度で選び直す）で戻るかを見る。
- 似たマスが多い所で、小さい k では決まらない恐れ（未確認）。
- 「10年前・80年代の技術」（11/6 の指摘）そのもの。新しさは主張しない。比較の基準と、学習で直す案の出発点として使う。

### 5.2 学習で直す案（改）の設計

**何をするか**

1. 基準案で u₀(p) を出す。
2. 各マスで、u₀(p) の周り 5×5 の類似度（表 C から引くだけ。新しい特徴の計算はない）と、現フレームの特徴（256ch を 1×1 の畳み込みで小さくしたもの）を並べ、64×64 の上の 3×3 の畳み込み数層に通す。出力は直し Δu(p)（±2 マスに制限）と信頼度 c(p)。
3. u = u₀ ＋ Δu。必要なら 2. を K 回くり返す（K = 1・2・4 を比べる）。
4. W を作る段は基準案と共通。信頼度が低いマスの扱い（動かさない／A-b の softmax に戻す）も同じ口で比べる。

# A-b の対応付けを位置合わせ付きにする：ブロックの平行移動（基準案）と、非線形な運動へ広げる差し替え口 Spec

## 目的

A-b（潜在特徴の対応で V3 の64段の state を運ぶ）の枠組みは変えず、対応付けだけを「局所ブロックごとの平行移動」に差し替える。これを比較の基準にする。同時に、対応付けを比べる診断を、運動の種類（①平行移動 ②アフィン ③非剛体）ごとに測れる形にし、次に作る学習ベースの対応付けを同じ口・同じ指標で比べられるようにする。

## 背景

- 11/12 の計測：A-b の対応は、物体の内側の並びが崩れている（隣と1マス以上ずれる辺 33%、RAFT 4%。折り返し 17%、RAFT 2%）。遅い層では、A-b の移動は動かさない場合より RAFT から遠い（0.68 と 0.46 マス）。
- 11/13 MTG の決定：位置合わせ付き（平行移動のみ）の対応付けから実装する。対応付けは差し替えられる形にする。学習ベースの方法は、回転などに対応できるかを試す。
- 11/16 の位置づけ（ユーザー）：平行移動のみは基準。目標は非線形な運動への対応で、学習ベースが本命の候補。
- 11/16 の事前確認（RAFT を参照、CPU だけ）：物体ごとに1つの平行移動から1マスより離れるマスは 14%（速い層 28%）。9×9 のブロックなら 5%（10%）。1フレームの回転は平均 2.6°、拡大縮小 4%。A-b の移動を物体の中で多数決するだけで、RAFT との差は A-b・動かさない場合を全層で下回った。

## 検証したい問い

1. ブロックの中で類似度を足してから移動を選ぶと、内側の並びと移動の正しさは、A-b・動かさない場合より良くなるか。どのブロックの大きさで。
2. その代わりに失うもの（外形、境界・遮蔽での誤り）はどれだけか。
3. 運動の種類ごとに、基準案はどこで足りなくなるか（学習ベースの対応付けが埋めるべき所はどこか）。
4. 基準案で Mamba を学習すると、運んだ state への依存・state の寄与は A-b より増えるか。

## 仮説

- H1：類似度を足すと、正しい移動先の順位が上がり、RAFT との差が全層で A-b・動かさない場合を下回る。
- H2：②は、9×9 以下のブロックなら平行移動で近似できる（合成の②で、誤差が①と同じ程度）。
- H3：誤差は、③（どちらでも合わないマス）と物体の境界に残る。
- H4：基準案で学習した V3 は、依存（推論だけ動かさない場合との差）と state の寄与（毎フレーム reset との差）が A-b 以上になる。

### 2. 予備計測で分かったこと（小さい標本。全量で確かめ直す）

1. **同じ動きの大きさで比べると、動きの内訳は MOSE と DanceTrack でほぼ同じ。** 1つの平行移動で合うマスは、動きが 0.25 マス未満で 96%・94%、0.62〜1.23 マスで 76%・75%、1.23 マス以上で 62%・64%（DanceTrack・MOSE、閾値 0.5 マス、RAFT を参照）。
2. **違うのは動きの大きさの分布。** DanceTrack は 20 fps で、box の中心は1フレームに中央値 0.18 マスしか動かない。1フレーム差の組の 61% が 0.25 マス未満（MOSE は 25%）。4フレーム差で MOSE と同じ程度になる。
3. **DanceTrack の1フレーム差では、物体のマスの 92% が1つの平行移動で合う**（アフィン変換なら合う 6%、どちらでも合わない 2%）。9×9 のブロックの平行移動で合わないマスは 3%（MOSE 6%）。
4. **参照を DIS に替えると、合わないマスは増える。** 9×9 のブロックで DanceTrack 6%・MOSE 19%。RAFT が部分ごとの動きを小さく見ている分と、DIS の誤りの両方が入るので、「RAFT の値〜DIS の値の間」としか言えない。
5. **対応する元が分からないマスは無視できない。** 1フレーム差で DanceTrack 8%・MOSE 21%。DanceTrack の4フレーム差で 30%、重なりが外れた直後で 18%（4フレーム差 46%）。DanceTrack では、box の3割以上が他の box に覆われる物体×フレームが 60% ある。

**設計への意味（私の読み）**

- **「DanceTrack は MOSE より非線形な動きが多い」とは、今のところ言えない。** 1フレームあたりでは、DanceTrack の方が平行移動に近い。部分ごとの動き（手足）は、1フレームでは 64×64 のマスの大きさより小さい動きにとどまっている（1マスの中のばらつきが 0.25 マスを超えるマスは 3%）。
- **データセットをまたぐときに効いてくるのは、動きの種類より、動きの大きさの幅。** 1フレームに 0.1 マスしか動かないデータ（DanceTrack）から、数マス動くデータ（MOSE の速い物体）までを、同じ方式で扱う必要がある。
- **1マス未満の動きの運び方が、DanceTrack では中心の問題になる。** 今日の基準案の設計で軽く扱っていた点。
  - 整数マスで運ぶと、1フレーム 0.18 マスの動きは毎回0に丸められ、state は一度も動かない（今の V3 と同じ）。物体は約5フレームで1マス進むので、state は置いていかれる。
  - 毎フレーム双線形補間で運ぶと、state がぼやける。小数部分が a のとき、1回ごとに広がり（分散）が a(1−a) マス²増える。0.18 マス/フレームなら、20フレーム（1秒）で標準偏差 約1.7マス、100フレームで 約3.8マス（計算上の値。Mamba は毎フレーム state を書き換えるので、実際の影響は state がどれだけ残るかによる。未計測）。人物の box の幅は中央値 5.5 マス。
  - 対策の候補：運ばなかった端数をマスごとに持ち越し、たまって1マスを超えたら整数マスで運ぶ（ぼやけず、位置の誤差は 0.5 マス以内）。端数は state と一緒に運ぶ。W を作る段の方式として、双線形・整数・端数の持ち越しの3つを同じ口で比べる。
- **学習ベースを本命にする理由は、「回転・変形に対応する」より、次の3つの方がデータと合う。** (a) 1マス未満から数マスまでの動きを、同じ精度で出す。(b) 対応する元が分からないマス（遮蔽、重なりが外れた直後）を、信頼度で見分ける。(c) 似たマスが多い所で、小さい範囲でも移動を決める。部分ごとの動きへの対応は、RAFT と DIS で見え方が割れているので、全量の診断と、別の物差しで確かめてから言う。
- **学習なしの基準案は、データセットによらない（学習していないので）。** 学習ベースを本命にするなら、「MOSE で学習したものが、DanceTrack で基準案を下回らない」を最初の条件にする必要がある。

| フレームの組 | 1本あたり等間隔に12フレーム。間隔は MOSE 1・2・4、DanceTrack・SportsMOT 1・2・4・8 |
| 参照の動き | RAFT large と DIS（medium）。どちらも 1024×1024 |
| 出す値 | 物体の動きの大きさの分布／1つの平行移動・アフィン変換・ブロック（3・5・9・15）で合うマスの割合（閾値 1・0.5・0.25 マス）／画素ごとの当てはめ／1マスの中のばらつき／分からないマスの割合／回転・拡大縮小の大きさ／RAFT と DIS の一致 |
| 層別 | 物体の動きの大きさ（データセットをまたいで同じ区切り）、間隔、重なり（今重なっている／外れた直後／重なりなし） |
| 時間 | DanceTrack 約34分、MOSE 約51分（RTX A4000）。SportsMOT は系列数しだい |

- **フレームが飛ぶ場合**：間隔 2・4・8 で測る。DanceTrack の 4フレーム差が、MOSE の1フレーム差と同じ程度の動きになる。7マス（A-b の窓）を超える組の割合も出す（DanceTrack val の box では、8フレーム差で 1.1%）。
- **遮蔽のあと**：測れるのは「重なりが外れた直後の組で、対応する元が分からないマスがどれだけあるか」まで。隠れている間をまたいだ動きは、flow では測れない（元が写っていない）。DanceTrack は GT の box どうしの重なり、MOSE は見えている面積の増え方で分ける。
- **RAFT が部分ごとの動きを小さく見る偏りへの対策**（スクリプトに入れた）
  - 前後の flow が食い違うマスは「分からない」とし、合うものとして数えない。
  - マスに平均する前の画素で当てはめる。1マスの中のばらつきを出す。
  - 物体のマスクの中の画素だけで平均する（境界で背景を混ぜない）。
  - DIS でも同じ値を出し、RAFT を下限、DIS を上限の目安として幅で報告する。
- **入れていない対策（必要なら足す）**
  - 点追跡の手法（CoTracker3 など）を3つ目の参照にする。重みの入手が要る（未確認）。
  - 人が付けた点の軌跡があるデータ（TAP-Vid-DAVIS）で、RAFT・DIS の「合わない」の割合が正解とどれだけずれるかを測り、幅を狭める。データの入手・形式は未確認。
- **全量のコマンド**は実験ログの「全量のコマンド」。長いので、ユーザーが tmux で実行する。

### 4. spec 案の位置づけの直し

上の spec 案（コードブロック）のうち、次を置き換える。保存するときに1本にまとめ直す。

**題**：A-b の対応付けを位置合わせ付きにする：データセットをまたいで使える学習ベースの対応付け（本命）と、ブロックの平行移動（基準）

**構成**

| 段階 | 内容 | 位置づけ |
|---|---|---|
| 0-データ | 動きの内訳の診断（上の 3.）。MOSE・DanceTrack・（SportsMOT） | 設計値と分岐を決める |
| 0-方式 | 対応付けの比較台（今日の 4.5 の A〜D）。MOSE に加えて、DanceTrack train でも同じ指標を測る（運んだマスクの IoU は SAM2 のマスクで代用）。1マス未満の動きを何フレームも続ける合成の試験を足す | 学習なしで方式を比べる |
| 1 | 基準案：ブロックの平行移動。11/13 MTG の合意どおり最初に作る。**最小限**にとどめ、重み付きの変種・信頼度での切り替えは入れない。1マス未満の運び方（双線形・整数・端数の持ち越し）だけは、DanceTrack で必須なので入れる | 比較の基準、学習ベースの出発点 |
| 2 | **学習ベースの対応付け（本命）**。基準案の移動から始めて直す。対応付けの部品だけを MOSE で学習し、DanceTrack・SportsMOT では学習なしで確かめる | 本命 |
| 3 | Mamba の学習と追跡の評価。MOSE val。DanceTrack val の評価は 11/6 の評価 spec（draft）の設定で、先生と時期を確認してから | 最終の評価 |

**分岐（段階0-データの全量の結果で決める。値は結果を見る前に置く）**

各データセットの1フレーム差（実際に使う間隔）で見る。

| 問い | 測る値 | 条件 | 条件を満たしたときの設計 | 予備計測 |
|---|---|---|---|---|
| Q1 部分ごとの動きは、ブロックの平行移動で足りないほど多いか | 9×9 のブロックで合わないマス（閾値 0.5 マス） | どれかのデータセットで RAFT 10% 以上 | 学習ベースは「移動の場を直す」ところまで作る（今日の 5.2） | RAFT：DanceTrack 3%・MOSE 6%（満たさない）。DIS：6%・19% |
| Q2 1マス未満の動きが主か | 物体の動きが 0.5 マス未満の組の割合 | どれかのデータセットで 50% 以上 | 基準案・学習ベースとも、1マス未満の運び方を必須にする。学習ベースは小数の移動を出す | DanceTrack は 0.62 マス未満が 86%（満たす見込み） |
| Q3 対応する元が分からないマスが多いか | 分からないマスの割合 | どれかのデータセットで 10% 以上 | 学習ベースは信頼度を出す。低いマスの扱いを比べる | MOSE 21%（満たす）。DanceTrack 8% |

- **Q2 か Q3 を満たす（予備計測では満たす見込み）**：学習ベースを同じ spec の段階2として前に出す。別の spec にはしない。理由は、基準案だけでは DanceTrack の主な動き（1マス未満）と遮蔽を扱いきれず、基準案の診断と学習ベースの設計を分けると、同じ比較台を2回作ることになるため。
- **Q1 も満たす**：段階2は、移動の場を直すところまで（5.2 の全部）。
- **Q1 を満たさない（予備計測の RAFT の値ではこちら）**：段階2は、小数の移動と信頼度を出すところから始める。移動の場を大きく直す部分は、段階0-方式で基準案の誤差が残った所（速い物体、DIS が「合わない」と言うマス）に絞って足す。Q1 は RAFT と DIS で割れているので、TAP-Vid-DAVIS などの正解で幅を狭めてから決め直す余地を残す。
- **どれも満たさない**：学習ベースは別の spec のまま後に回し、基準案を仕上げる。
- SportsMOT が手に入っていない間は、MOSE と DanceTrack で決め、入手後に同じ表を埋めて確かめ直す。

**汎化を設計に入れる**

- **入力をデータセットによらない量にする。** 学習ベースの入力は、類似度の表から引いた値（cos 類似度）と基準案の移動を主にする。現フレームの特徴（256ch）を入れるかは、下の「学習していないデータでの誤差」で決める（入れた方が MOSE では良くても、DanceTrack で悪くなるなら入れない）。
- **動きの大きさの幅を、学習で覆う。** MOSE の1フレームの動き（中央値 0.63 マス）は DanceTrack（0.18〜0.22 マス）より大きい。合成の教師では 0〜7 マスを、1マス未満を厚くして振る。疑似ラベルは、間隔 1・2・4 の組を混ぜる。物体の大きさも振る（DanceTrack の人物は 5.5×18 マス）。
- **疑似ラベルは、RAFT と DIS が一致するマスだけを使う。** 片方の手法の癖を覚えないようにする。
- **学習前は基準案と一致させる**（直しを0から始める）。学習ベースが外したときの下限が、データセットによらない基準案になる。

**汎化を評価に入れる**

| 段 | 何を測るか | データ | 合格の条件（案） |
|---|---|---|---|
| 対応の正しさ（学習なしで他のデータへ） | MOSE で学習した対応付けの部品を、そのまま DanceTrack train・SportsMOT に当てる。参照（RAFT と DIS が一致するマス）との差を、動きの大きさの層ごとに出す | MOSE tuning、DanceTrack train、SportsMOT train | どのデータセット・どの層でも、基準案より悪くならない（物体ごとの対の差の区間）。0.25 マス未満の層で、動かさない場合より悪くならない。速い層で基準案を下回る |
| 1マス未満を続けたとき | 合成で 0.1〜0.5 マス/フレームの動きを 50〜100 フレーム続け、運んだものの位置のずれと広がりを測る | 合成 | 位置のずれ 0.5 マス以内。広がりが双線形補間より小さい |
| 追跡の性能 | MOSE val の J&F・依存・state の寄与。DanceTrack val の HOTA | MOSE val、DanceTrack val | 既存の基準（A-b の spec）。DanceTrack は時期を先生と確認 |

- 1段目は、DanceTrack を使うが、追跡の評価ではなく対応付けの部品の診断。ただし「DanceTrack での評価」と受け取られる恐れがあるので、MTG で位置づけを先に言う。
- Mamba 本体（MOSE で学習）が DanceTrack で効くかは、対応付けとは別の問題。この spec では扱わず、段階3の評価で見る。
