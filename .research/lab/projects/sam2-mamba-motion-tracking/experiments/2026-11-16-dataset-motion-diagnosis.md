# データセットごとの動きの内訳の診断（MOSE・DanceTrack）

位置合わせ付きの対応付けの設計のために、データの中の物体が SAM2 の 64×64 マスの上でどう動くかを、MOSE と DanceTrack で同じ方法で測る。**手法の評価ではない。** 追跡器も adapter も動かさず、学習もしない。データの動きを optical flow で調べるだけの診断である（11/6 MTG の「DanceTrack での評価より先に A-b を突き詰める」とは別の作業）。

11/16 にスクリプトを作って小さい標本で予備計測をし、11/17 に全量を測った。SAM2 repo のコードは変えていない。SportsMOT は手元になく、測っていない（入手できたら同じ診断を追加する）。

スクリプトと出力：[figures/2026-11-16-dataset-motion-diagnosis/](figures/2026-11-16-dataset-motion-diagnosis/)（`motion_diag.py`、`box_motion.py`、`data/dancetrack/`・`data/mose/` が全量、`data/prelim_*/` が予備計測）。図はない。

## 結論（全量、2026-11-17）

RAFT を参照。「合う」の閾値は、断りがなければ 0.5 マス。

- **DanceTrack は、1フレームの動きが小さい。** 物体の動きの中央値は 0.14 マス。1フレーム差の組の 86% が 0.5 マス未満（MOSE は 39%、中央値 0.74 マス）。
- **同じ動きの大きさで比べると、動きの内訳は2つのデータで近い。DanceTrack の方が数ポイント、平行移動に近い。** 予備計測の「ほぼ同じ」は、全量では差が少し開いた。

  | 物体の動き（マス/組、1フレーム差） | DanceTrack：1つの平行移動で合うマス | MOSE：同左 |
  |---|---|---|
  | 0.25 未満 | 97% | 90% |
  | 0.25〜0.62 | 93% | 83% |
  | 0.62〜1.23 | 79% | 74% |
  | 1.23 以上 | 70% | 62% |

- **データ全体で見ると、違いは大きい。** 1フレーム差で、1つの平行移動で合うマスは DanceTrack 95%（アフィン変換なら合う 4%、どちらでも合わない 2%）、MOSE 76%（16%・9%）。動きの大きさの分布の違いによる。
- **ブロックを小さくすれば、平行移動でほぼ合う（RAFT を参照）。** 9×9 のブロックで合わないマスは DanceTrack 2%・MOSE 6%。3×3 なら 0.4%・1%。
- **動きの大きい層（1.23 マス以上）では、9×9 のブロックで合わないマスが1割前後ある。** DanceTrack 12%（区間 10〜15%、76物体）、MOSE 9%（8〜11%、226物体）。ただし DanceTrack でこの層に入るのは、1フレーム差の組の 2% だけ（MOSE は 34%）。
- **参照を DIS に替えると「合わない」が増える。** 9×9 のブロックで、全体では DanceTrack 5%・MOSE 20%、動きの大きい層では 27%・28%。RAFT と DIS が 0.5 マス以内で一致するマスは、DanceTrack 96%・MOSE 80%。部分ごとの動きの割合は、RAFT の値〜DIS の値の幅でしか言えない（予備計測と同じ）。
- **対応する元が分からないマスは、間隔と遮蔽で増える。** 1フレーム差で DanceTrack 6%・MOSE 21%。DanceTrack は間隔 2・4・8 で 16%・32%・47%。重なりが外れた直後は 16%（4フレーム差で 52%）。MOSE で見えている面積が25%以上増えた組は 46%。DanceTrack で「今重なっている」組は、重なりのない組と変わらない（6% と 6%）。
- **1フレームあたりの回転・拡大縮小は小さい。** DanceTrack 1.3°・1.7%、MOSE 2.2°・3.4%。
- **予備計測の読みは、全量でも変わらなかった。** 変わったのは、同じ動きの大きさでの2つのデータの差（数ポイント開いた）だけ。

## 予備計測の結論（2026-11-16、小さい標本。参考として残す）

- **DanceTrack は、1フレームの動きが小さい。** GT の box の中心の移動は、val 273トラックの中央値で 0.18 マス/フレーム。全トラックが MOSE の「遅い」層（0.62 マス未満）に入る。4フレーム差で 0.63 マス、8フレーム差で 1.09 マスになる。
- **同じ動きの大きさで比べると、動きの内訳は MOSE と DanceTrack でほぼ同じ。** 違うのは、動きの大きさの分布の方。

  | 物体の動き（マス/組） | DanceTrack：1つの平行移動で合うマス | MOSE：同左 |
  |---|---|---|
  | 0.25 未満 | 96% | 94% |
  | 0.25〜0.62 | 89% | 86% |
  | 0.62〜1.23 | 76% | 75% |
  | 1.23 以上 | 62% | 64% |

  （1フレーム差、閾値 0.5 マス、RAFT を参照。20マス以上の物体）
- **DanceTrack の1フレーム差では、物体の動きの6割が 0.25 マス未満。** 1つの平行移動で合うマスは 92%（アフィン変換なら合う 6%、どちらでも合わない 2%）。閾値を 0.25 マスにすると 79%・12%・9%。
- **ブロックを小さくすれば、平行移動でほぼ合う（RAFT を参照）。** 9×9 のブロックの中央値から 0.5 マスより離れるマスは、DanceTrack 3%・MOSE 6%。3×3 なら 0.5%・1%。
- **ただし、参照を DIS に替えると「合わない」が増える。** 9×9 のブロックで合わないマスは、DanceTrack 6%・MOSE 19%。RAFT と DIS の移動が 0.5 マス以内で一致するマスは、DanceTrack 95%・MOSE 83%。RAFT の値は下限、DIS の値は上限の目安として読む（DIS の誤りも入る）。
- **対応する元が分からないマス（RAFT の前後の flow が 4 画素より食い違う）は、間隔と遮蔽で増える。** DanceTrack：1フレーム差 8%、4フレーム差 30%。他の物体の重なりが外れた直後は 18%（4フレーム差で 46%）。MOSE：1フレーム差 21%、見えている面積が25%以上増えた組では 50%。

## 方法

- **対象**
  - MOSE：train の tuning 125動画（11/12 と同じ動画・物体）。正解マスクを使う。
  - DanceTrack：train 40系列（`dataset/DanceTrack/train1`・`train2`）。val は評価に使うので使わない。マスクがないので、各フレームで GT の box を SAM2.1 large にプロンプトとして渡し、マスクを作った（追跡はしない。1フレームずつ独立）。マスクの外接矩形と GT の box の IoU が 0.5 未満のものは除く。1フレーム（dancetrack0002 の600フレーム目）を目で見て、人物ごとに分かれていることを確かめた。
- **フレームの組**：各動画・系列で等間隔に取ったフレーム t と、t − 間隔。全量は t が1本あたり12、間隔は DanceTrack 1・2・4・8、MOSE 1・2・4。予備計測は t が1本あたり 4（DanceTrack）・3（MOSE）、間隔は 1・4（DanceTrack）、1・2（MOSE）。
- **参照の動き**：RAFT large（torchvision、更新12回、1024×1024）の t → t−間隔 の flow。別の手法として DIS（OpenCV、medium の設定、1024×1024）。
- **分からないマス**：RAFT の前向き・後ろ向きの flow が 4 画素（0.25 マス）より食い違う画素は「分からない」とし、当てはめに使わない。物体の画素の半分以上が分からないマスは「分からないマス」。11/13 の厳しい基準（約 0.7 画素）での割合も記録した（`valid_px_strict`）。動きが小さいデータでは、厳しい基準だと flow の小さなノイズで多くが落ちる（DanceTrack で一致する画素は 68%、4 画素の基準で 90%）。
- **マスの移動**：物体のマスクの中で、分かっている画素だけの flow を 16×16 のマスごとに平均する（境界で背景が混ざらない）。
- **当てはめ**：物体ごとに、(1) 1つの平行移動（中央値）、(2) アフィン変換、(3) k×k のブロックの中央値（k = 3・5・9・15）。残差が 1・0.5・0.25 マスを超えるマスの割合。
- **RAFT が部分ごとの動きを小さく見る偏りへの対策**
  - 上の「分からないマス」を、合うものとして数えない。
  - 画素ごとの当てはめ（物体の中央値の flow から 0.5 マス相当より離れる画素の割合）も出す。
  - マスの中の flow のばらつき（1マスの中に2つの動きがあるか）を出す。
  - DIS でも同じ値を出し、RAFT と並べる。
- **層別**：物体の動きの大きさ（組ごと。0.25 未満／0.25〜0.62／0.62〜1.23／1.23 以上。区切りは MOSE の速さの3層の区切り＋1マス未満用の 0.25）、他の box との重なり（DanceTrack）、見えている面積の増え方（MOSE）。
- **集計**：物体ごとに組の平均 → 物体の平均。区間は物体の bootstrap 95%（2,000回、seed 123）。

## 注意

- 予備計測は1本あたり t が 3〜4 フレームの小さい標本だった。全量（12フレーム）でも読みは変わらなかった。
- RAFT も DIS も正解の動きではない。DanceTrack・MOSE には点の正解の軌跡がないので、③（部分ごとの動き）の本当の割合は分からない。RAFT と DIS の値の間、という幅でしか言えない。
- DanceTrack のマスクは SAM2 が作ったもの。重なった人物では、手前の人物が混ざる可能性がある。目で確かめたのは1フレームだけ。
- 動きの大きさの定義が 11/4 の計測（縦横の大きい方）と少し違う（今回は長さ）。層の区切りは MOSE の値をそのまま使った。
- 全量は、DanceTrack を RTX A4000、MOSE を RTX PRO 4500 で測った（並列にするため）。GPU の違いは、flow の値の丸め誤差程度と見ている（確かめてはいない）。
- 動きの大きい層の DanceTrack（1フレーム差）は 88行・76物体と少ない。
- 予備計測のあとで、スクリプトを MOT 形式の他のデータ（SportsMOT など）も読めるように直した（画像の一覧の作り方）。全量はこの版で測った。
- SportsMOT はローカルにも NAS にも見つからない。入手してから同じスクリプトで測る。
