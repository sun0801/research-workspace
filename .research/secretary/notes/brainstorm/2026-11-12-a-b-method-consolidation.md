## 今回見えた方向性（今日の判断）

### これまでがうまくいかなかった理由（記録から読めること）

- **棄却の理由は、実装や結果ではなく「設計の根拠」と「面白さ」だった。** 11/6 の指摘は「7×7 の根拠が言えない」「簡単そうだったからは理由にならない」「10年前・80年代の技術」「やろうと言ったものを突き詰めていない」。どれも、実装の前に紙の上で指摘できた内容。
- **Deep Research では「どう入れるか」を聞き、「なぜ効くはずか」を詰めていなかった。** 11/2 のサーベイは冒頭で、強い attention memory の上に足した recurrent state の寄与は一貫して小さい（反対仮説 (a)）と書き、state の存在意義を置き直すよう提案していた。その前提の問いを置いたまま、入れ方の比較（②・②'、A-b）に進んだ。
- **評価で決着がつかない。** val では 1 pp 未満の差を判定できず、A・②・②'・A-b はすべて「区間が 0 を含む」で終わった。先生から見ると判断材料がなく、次の案へ移るしかなかった。

### 決めたこと

- **A-b を軸にする。** 理由は次のとおり。
  - 11/6 MTG の決定事項が「①-b を主軸に突き詰める」。ここで別の案に移ると、「やろうと言ったものを突き詰めない」という指摘を繰り返すことになる。
  - これまで試した中で、state の依存・寄与・性能の点推定がそろって正になったのは A-b だけ（区間は 0 を含む）。
  - 先生は「潜在表現で対応を取る方向性はよい」と言っている。
  - 段階0の診断・adapter・評価の仕組みがすでにある。
- **進め方は「設計を先生に通してから実装する」。** 実装してから見せる順番をやめる。
  1. 先生の過去の指摘を、設計レビューの観点表にする（下の節）
  2. Fable に、A-b の弱点ごとの直し方を調査付きで出させる
  3. 有望な組み合わせを、2〜3個の完成した設計にまとめる（修論の手法の節の形）
  4. 観点表で敵対的にレビューし、1〜2案に絞る
  5. 実装の前に先生に設計をレビューしてもらう。合意が取れた時点で「手法が固まった」とし、その後は改善だけに絞る
- **Fable の使い方**：このセッションで `/model` から Fable に切り替え、この brainstorm を続けて設計を詰める。サブエージェントに丸投げすると要約しか返らないので、使わない。
- **新しいアイデアの扱い方**：思いついた案は下の「保留リスト」に入れるだけにする。採用するのは、A-b の弱点として確認できたもの（形の崩れ、1マス未満の動き、state の複製、state の寄与が小さいこと）のどれかを直す案に限る。それ以外は、手法が固まるまで実装しない。
- **差し替え口の出力は W（対応の重み）で統一する。** 「移動場（1マス1本の矢印）＋補間ワープ」も、近くの4マスにだけ重みがある W として書けるので、候補の1つとして並べる。どちらか一方を選ぶ必要はない。
- **明日（11/13）の MTG**：今の A-b（softmax）の形の崩れの図と数値を見せる（11/12 に作成済み、MTG 資料に記録済み）。「手法を固めたいので、次回は実装ではなく設計案を持ってくる。レビューしてほしい」と提案し、先生が手法2の貢献をどこに見ているかを聞く。

## アイデア候補（A-b の弱点の直し方。発散の入口で、まだ評価していない）

- コストボリュームの平滑化：softmax の前に、類似度を空間方向にぼかす（ガイデッドフィルタなど）
- 移動場の平滑化＋補間ワープ：W から各マスの移動ベクトルを作り、平滑化してから bilinear で state を運ぶ（1マス未満の動きも表せる。A-a の flow を同じ口に差し込める）
- 滑らかさの制約付きの最適化：Horn–Schunck、MRF、Semi-Global Matching など（コストボリュームは 64×64×225 と小さい）
- 前向き・後ろ向きの一致チェック：一致しないマスは identity に戻すか、state をリセットする
- 物体単位のアフィン当てはめ：前フレームのマスクで前景のマスにアフィン変換を当てはめる
- PatchMatch 型の伝播、coarse-to-fine（SAM2 の FPN の細かい段の特徴で対応を取る）
- 学習で対応を取る（RAFT 型の反復更新、学習する τ や特徴の射影）

## 仮説候補

- H-a：A-b の形の崩れ（隣どうしのマスがばらばらな場所から state を持ってくる）が、state の寄与を小さくしている。空間的な制約で崩れを減らせば、運んだ state の寄与（U_id・R）が増える。
- H-b：1マス未満の動き（MOSE の中央値 0.63 マス）を補間ワープで表せば、遅い物体の層で、運ぶことによるぼやけが減る。
- 反対仮説：崩れを直しても、SAM2 の memory attention が時間対応を担っているので、state の寄与は小さいまま（11/2 サーベイの反対仮説 (a)）。

## Fable への入力のまとめ

> この節は、Fable がこれだけを読めば設計に入れるように書いた。数値は実験ログ・議事録からの引用。

### 1. 研究の枠組み

- テーマ：SAM2 に Mamba で時系列情報を組み込む。修論では、組み込み方の1つ目が手法1（動き予測：SAMURAI のカルマンフィルタを Mamba に置き換える）、2つ目が手法2（特徴表現：SAM2 の中に temporal Mamba を入れる）。今回固めたいのは手法2。
- 論文・修論の書き方（10/23 の先生の指摘）：研究の経緯ではなく、「SAM2・SAMURAI・SAM2MOT のすべてに Mamba を入れ、空間・時間の両方を提案する」形で書く。修論は、全部組み込んだ提案を 2027年2月までに。

### 2. 今の構成（V3 と A-b）

- **V3**：SAM2.1 のデコーダの手前に、FPN 的に複数段（そのうち 64×64 の段を含む）の temporal Mamba を入れる。マスごとに、時間方向に Mamba を1歩ずつ進める（メモリの制約のため、全マスを1本の系列にはしていない）。state は画面上の位置に固定。SAM2 本体（エンコーダ・デコーダ）は固定し、Mamba だけを学習する。
- **A-b**：V3 の 64 段だけ、Mamba を1歩進める前に、前フレームの state を潜在空間の対応で運ぶ。
  - 特徴：画像エンコーダの stride 16 特徴（`current_vision_feats[-1]`、64×64・256ch）。チャネル方向に L2 正規化し、cos 類似度 s(p, q) を取る。
  - 範囲：各マス p について、前フレームの p を中心とする 15×15 マス（±7マス）の窓。窓の外と画面の外は −∞。
  - 対応の重み：行ごとに softmax(s/τ)、τ = 0.02。行の和は 1、列の和に制約はない。
  - 運ぶもの：64 段の ssm_state と conv_state。h'(p) = Σ_q W(p, q) h(q)。FP32 で計算し、W には勾配を流さない。
  - 追加の学習パラメータはない（学習パラメータは A と同じ 570,563 個）。
  - 学習：MOSE、8フレームの短い区間、22 epoch（24,662 更新、1更新の平均 1.98 秒、RTX A4000）。
- 方式の選び方：段階0（学習なしの診断、100動画・12,596組）で、画像エンコーダ特徴・`pix_feat` × softmax・sinkhorn を比べ、関門を通ったのは「画像エンコーダ特徴・softmax・τ=0.02」だけだった。

### 3. これまでの結果

**A-b より前（state が使われていない）**

- 10/8（全軌跡の学習）：F1 − F0 = +0.00282 [−0.00669, +0.01157]、state を毎フレーム reset した場合との差も 0 を含む。adapter の LR が小さすぎて実質未学習だった（10/9 の事後診断）。
- 10/30（8フレームの区間の学習）：Mamba の有無の差と、推論時の state の reset の差は、すべて 95% 区間で 0 を含む。今の V3 は、時間方向の記憶をほぼ使っていない。
- 11/5（B：②・②'）：state の寄与の増加 I は、② が +0.01 [−1.00, +1.08]、②' が +0.07 [−0.45, +0.62]。②' は A より性能が低い傾向（−0.86 [−1.87, −0.04]）。SAM2 の memory を直近1枚に絞っても、A の state の寄与は確認できなかった（+0.75 [−0.14, +1.91]）。

| 特徴・方式 | M（同じ物体から運べる state の質量） | H（同一物体率） | 行の和 | 前景の複製（列の和 > 1.5 の割合） |

| identity（今の V3） | 0.606 | 0.606 | 1 | 0 |

- 1マス未満の移動（0.25・0.5 マス）では、softmax の位置の誤差の中央値は 0.36〜0.78 / 0.65〜1.17 マスで、identity（0.25〜0.35 / 0.5〜0.71）より大きい。MOSE の動きの中央値は 0.63 マス。

**評価（MOSE val、125動画・313対象、単一 seed、J&F、pp、動画単位の paired bootstrap 95% 区間）**

J&F（動画平均）：A-b 0.7853、A-b-reset1 0.7794、A-b-id 0.7797、A-b-shuf 0.7826、A' 0.7789、A'-reset1 0.7792、F0 0.7701（A' は A と同じ設定を A-b と同じ GPU で学習し直したもの）。

- 固定した 200 区間の train loss では、A-b と A' の差は、どの epoch でも A' と A の差（GPU の違いによるばらつき）と同じ程度。
- 評価中の W の統計：期待移動距離 2.02 マス、エントロピー 1.27、列の和の最大 6.92。

### 4. A-b の弱点

| 弱点 | 状態 | 根拠 |
|---|---|---|
| 形の崩れ：各マスが独立に移動先を選ぶので、隣どうしのマスがばらばらな場所から state を持ってくる | **確認済み（11/12）。外形は保つが、物体の内側の並びが崩れる** | 隣のマスと移動が1マス以上違う辺 A-b 33%（遅い19%・速い45%）・RAFT 4%。折り返し A-b 17%・argmax 39%・RAFT 2%。運んだマスクの IoU は A-b 0.76 で RAFT 0.67・identity 0.58 より高い（同一物体は当てる）。遅い層では A-b の移動は RAFT から identity より遠い（0.68・0.46マス）。[実験ログ](../../../lab/projects/sam2-mamba-motion-tracking/experiments/2026-11-12-latent-corr-shape-coherence.md) |

### 5. 先生が肯定した方向・示した指針

- 潜在表現で対応を取る方向性はよい（11/6）。研究として面白いのは潜在空間の中で対応を取る方（10/30）。
- 類似度最大の対応は、ちょっとしたノイズで隣のマスがまったく違う所に行く。このアイデア自体は 80年代からあり、ばらばらにならないように上下左右に制約をかける方法もある。そういうものを入れ込む（11/6）。
- 対応付けのアルゴリズム（類似度最大、ハンガリアンマッチング、それ以外）を差し替えられる環境を作り、高度な手法を入れて、計算量と精度の関係を見る（11/6）。
- ハンガリアンマッチング（1対1）は、この応用では多対1の対応が必ずあるので、うまくいかない代表例になると思う（11/6）。
- 潜在空間では空間解像度が落ちるので、実用上は、画像空間でフローを取って潜在空間に写す方がよいと思う（10/30）。A-a は「中でやるか外でやるかの違い」で、A-b が主体（11/6）。
  - 11/11 の計測：DIS ultrafast は 1024×1024 で 14.8 ms、256×256 で 0.9 ms（CPU・1スレッド）。RAFT small は 1024 で 91 ms（RTX A4000）。SAM2 の1物体・1フレームは約 30 ms。
- 固定カーネルで混ぜるだけでは空間的にぼやけるだけで、面白くない。畳み込みまで学習する、Deformable Conv でやる、などならまだ分かる（11/6）。

### 6. 近い先行研究と、11/2 サーベイの要点

- **TS-Mamba**（ICLR'26、arXiv 2508.10453、オンライン動画超解像）：現在のトークンに対して、過去フレーム内の最も似たトークンを集め、1本の軌跡の系列として SSM に渡す。Hilbert 走査と shift で空間の連続性を補う。「state を座標ごとワープする案」と「軌跡の上で新しく state を作る案」を比べるときの参照になる。
- **11/2 サーベイの要点**（[本文](../../../lab/projects/sam2-mamba-motion-tracking/papers/2026-11-02-deep-research-spatial-correspondence-mamba-state.md)）：
  - 強い attention memory の上に足した recurrent state の寄与は一貫して小さい（XMem の sensory memory の除去で −1.1〜−1.9 J&F、Cutie の object memory は MOSE で −0.4、SAM2 著者の GRU memory は改善なし）。大きく効くのは、base が時間対応を持たない場合。
  - したがって null result は、反対仮説 (a)「SAM2 の memory が時間情報を担っており、recurrent state は冗長」と整合する。位置ずれ仮説とは排他でない。
  - state carry の存在意義は、「定数メモリでの memory 置換」と「動き・同一性の長期保持」に置くべき。
  - 最初に試す案として「flow で state を運ぶ warp-then-step（flow oracle 版）」を推した。移動が 0 なら今のモデルと完全に一致するので、比較が純粋になる。
  - 関連：AOT の局所 attention（前フレームの λ×λ 窓）、TrajGRU（state をワープしてから更新）、BasicVSR++（flow を基準の offset にした DCN。flow なしの DCN は崩壊）、HMMN（局所窓の追跡から Gaussian kernel を作る）。
- 11/6 の英論文紹介の調査の仮説：state carry の有無そのものより、(1) state がどの物理対象に対応しているか、(2) 今の観測を state に書くべきか、(3) 過去の state のどこを残す・消す・直すか、の3点を分けて設計・ablate する方がよい。

### 7. 制約

- SAM2 本体（エンコーダ・デコーダ）は固定し、Mamba（と対応付けの部品）だけを学習する。デコーダの cross-attention は触らない（10/30）。
- 開発中は 10 epoch 程度で傾向を見て設計を回し、設定が決まったら 30〜100 epoch で数字を出す（10/30）。
- 計算量：22 epoch の学習は RTX A4000 で約 13.5 時間（A-b）。対応付けの追加コストは、段階0a で「softmax は1更新あたり約 0.24 秒の追加」と記録している。一方、11/11 の比較では「A-b は類似度 0.8 ms＋softmax 0.3 ms」と書いている（測った条件が違う可能性がある。設計で使う前に確認すること）。
- GPU：142 の RTX A4000・RTX PRO 4500、141 の RTX A4000 など。本学習・本評価はユーザーが tmux で実行する。
- 締切：修論は 2027年2月までに、全部組み込んだ提案を。

## 追記 18:38（Fable：設計案の絞り込み）

> 「8. Fable への依頼」の3段階（発散 → 収束 → 敵対レビュー）を1回に圧縮して行った。ユーザーとの段階ごとの議論は挟んでいない。実験・学習は回していない。今日の数値はすべて上の節と[計測ログ](../../../lab/projects/sam2-mamba-motion-tracking/experiments/2026-11-12-latent-corr-shape-coherence.md)からの引用で、新しい数値はない。計算量は積和の回数の見積もりで、時間は測っていない。

### 0. 先に結論

- 先生に聞く2案は、**制約案**（隣のマスと移動をそろえる制約を、学習なしで入れる）と**学習案**（移動ベクトルを少しずつ直す小さなネットワークを学習する）。
- 2案は対立ではなく、同じ差し替え口に入る。制約案は λ=0 で今の A-b と完全に一致し、学習案の比較相手にもなる。聞きたいのは「主軸をどちらに置くか」。
- 私の推しは、**制約案を先に学習なしの指標で決着させ、学習案はその上に積むかを先生に聞く**順番。理由は、制約案は11/6の指示（上下左右の制約、差し替え、計算量と精度）にそのまま対応し、今日の計測スクリプトで数日で白黒がつくため。
- どちらの案も「内側の並びを直せば state の寄与が増える」（H-a）を前提にしている。この前提は未確認（計測ログの注意にあるとおり、並びの崩れが性能に効くかは測っていない）。反対仮説 (a) には、どちらの案も直接は答えない。

### 1. 今日の数値の読み直し（設計の出発点）

- A-b は 64×64 マス × 窓 225 マスの「類似度の表」（ステレオや optical flow でいうコストボリューム）を作り、各マスが独立に softmax を取っている。隣のマスの表は見ていない。
- 崩れ方は「物体の中に似たマスが多く、最も似たマスがばらばらに散る」（計測ログの解釈、未確認）。これは古典でいう、模様の少ない領域で対応が決まらない問題と同じ形。古典の答えは、(i) 隣と票を合わせる（集約・平滑化制約）、(ii) 移動ベクトルを1本にして滑らかにする、の2系統。
- 潜在の類似度と画像の flow は、得意な所が逆に見える：運んだマスクの IoU は A-b 0.76 > RAFT 0.67、隣と1マス以上ずれる辺は A-b 33% > RAFT 4%。ただし RAFT の IoU が低い理由（マス平均で縁に背景が混ざる）は未確認。
- 計算時間の食い違い（7. 制約の節の宿題）：[11/4 実験ログ](../../../lab/projects/sam2-mamba-motion-tracking/experiments/2026-11-04-temporal-mamba-latent-correspondence.md)の段階0aの表では、類似度 0.8 ms、softmax 0.3 ms、輸送の forward＋backward 29 ms。8フレームで (0.8＋0.3＋29)×8 ≈ 0.24 秒なので、「1更新 0.24 秒」の大半は W を掛けて state を運ぶ部分で、対応を決める部分ではない、と読める（私の計算。ログに内訳の明記はない）。

### 2. 発散：弱点ごとの直し方

### 3. 収束：設計案（3つ）

共通の前提（先生への説明で最初に言うこと）：

- メモリの制約のため、Mamba は 64×64 の各マスで別々に時間方向へ進めている。1マスの Mamba は本来そのマスの情報しか持たない。A-b は、Mamba を1歩進める前に、前フレームの他のマスの state を持ってくる。
- 記号は3つだけ使う。s(p, d)：現フレームのマス p と、前フレームの p から d だけ離れたマスとの類似度（d は 15×15 = 225 通り）。W：どのマスからどれだけ持ってくるかの重み。u(p)：マス p の移動ベクトル。
- 窓 15×15（±7マス）は変えない。根拠は MOSE の1フレームの動きの 95% 点が 4.16 マス（spec の段階0m）で、±7 はそれを覆う。11/6 議事録の ②・②' の 7×7（動きの 90% 点 2.80 マス）と同じ決め方。どの案も窓は共通にして、対応の決め方だけを変える。

#### 制約案：隣のマスと移動をそろえてから選ぶ（学習なし）

**何をするか**

1. 今の A-b と同じく、各マスで q⁰(p, d) = softmax_d( s(p, d) / τ )、τ = 0.02。
2. 次を T 回くり返す。

   q^{k+1}(p, d) = softmax_d( s(p, d)/τ ＋ λ · Σ_{p'∈上下左右} a(p, p') · Q^k(p', d) )

   - Q^k(p', d) = 隣のマス p' の移動が、d から縦横1マス以内に入っている確率（q^k(p', ·) を d の平面で 3×3 の和にしたもの）
   - a(p, p') = 現フレームの特徴で見た p と p' の類似度から決める 0〜1 の重み。物体の境界をまたぐ隣どうしでは小さくする
3. 運び方は2通りを同じ口で比べる。(i) W = q^T をそのまま使う（今と同じ、225マスの重み）。(ii) q^T の頂点の周り 3×3 だけで期待値を取って移動ベクトル u(p) にし、行き先の周り4マスから双線形補間で持ってくる（W は4マスだけ非0）。

**どの弱点を直すか**

- 並（隣とのずれ 33%・折り返し 17%）：2. の項が直接の対策。隣が「このあたりへ移動」と言っている候補の票が上がる。先生の言う「上下左右の制約」そのもの。
- 小（1マス未満）：3.(ii)。u = 0 なら今の V3（動かさない）と完全に一致する。遅い層で A-b の移動が動かさない場合より RAFT から遠い（0.68 と 0.46 マス）のは、似た候補に票が散るためと見ているので、2. で票がまとまれば縮む見込み（未確認）。
- 複（列の和 > 1.5 が約19%）：直接の制約は入れない。多対1（遮蔽・拡大）を許すため（先生の 11/6 の指摘、sinkhorn の失敗）。移動がそろえば、同じマスに集中する対応は減ると予想するが、未確認。指標として測るだけにする。

**設計の選択と根拠**

| 選択 | 値 | 根拠 |
|---|---|---|
| 隣の範囲 | 上下左右の4マス | 先生の指摘どおり。遠くへは反復で伝わる（T 回で T マス先まで） |
| 「そろっている」の幅 | 縦横1マス以内（3×3） | 今日の計測で、RAFT では隣と移動が1マス以上違う辺が 4%。つまり実際の動きでは、隣どうしの移動の差はほぼ1マス以内。「同じ移動」まで要求すると回転・拡大・変形を禁止してしまう |
| 境界の重み a | 現フレームの特徴の類似度 | A-b の長所（運んだマスクの IoU 0.76）は、物体の境界で対応が切り替わることから来ている。境界をまたいでそろえると、この長所を壊す。a のしきい値は、正解マスクで「同じ物体の中の隣どうし」と「境界をまたぐ隣どうし」の類似度の分布を測って、その間に置く（これから測る） |
| 制約の強さ λ・回数 T | 学習なしの指標で決める | λ=0 または T=0 で A-b と完全に一致。下の合格条件を満たす最小の λ・T を選ぶ（同等なら変更の少ない方）。T は 1・2・4・8 を比べ、計算量と精度の関係の図にする |
| τ | 0.02 のまま | 段階0で選んだ値。変えると A-b との比較が純粋でなくなる |

**最も近い先行研究との違い**

- 式そのものは、コストボリュームの上の MRF を平均場で解く古典の形（CRF-as-RNN、dense CRF、flow では DCFlow の SGM）。**アルゴリズムの新しさは主張できない。**
- 主張できるのは次の2点。(1) 固定した SAM2 の特徴の対応は「どの物体か」は当てるが「物体のどこか」は当てない、という今日の計測と、その隙間を学習なしの制約で埋められるかという検証。(2) 画像や特徴ではなく、Mamba の state を運ぶ対応に使っていること。TS-Mamba は（確認した範囲では）隣どうしの軌跡に制約を置いていない。
- ②・②'（固定の重みで混ぜる）との違い：混ぜるのは「どこへ移動するかの票」で、state そのものは混ぜない。state は決まった移動先から運ぶので、ぼやけない。

**計算量**：1回あたり 4096 マス × 225 候補 ×（3×3 の和 ＋ 4近傍）≈ 1,200万回の積和。類似度の計算（約2.4億回、実測 0.8 ms）の約 1/20。T=8 でも類似度の計算より少ない見込み（時間は未計測）。追加のメモリは 4096×225 の表1枚（約 3.7 MB/物体）。

**学習パラメータ**：なし（570,563 個のまま）。発展として λ と a のしきい値の2個だけ学習する形にもできる。

**制約との整合**：SAM2 本体・デコーダには触らない。W に勾配を流さない点も今と同じ。Mamba の学習設定は A-b と同じ。

**学習なしで比べられるか**：できる。今日のスクリプトに方式を1つ足すだけ。

**決着がつく最小の実験**（MOSE tuning 125動画・310物体、今日と同じ指標。合格条件は案で、数値は今日の計測から置いた）

- 隣と1マス以上ずれる辺・折り返しが、A-b の 95% 区間（0.313〜0.351、0.161〜0.187）より下がる。
- 運んだマスクの IoU が、A-b の区間の下限 0.743 を下回らない。
- 遅い層の RAFT との差が、動かさない場合の 0.46 マス以下になる。
- 段階0の合成のずらし（0.25・0.5 マス）で、位置の誤差が identity 以下になる（3.(ii) の確認）。
- 列の和 > 1.5 の割合は報告だけする。
- 全部を満たす設定がなければ、制約案は棄却する。満たせば、その1設定だけを 10 epoch 学習し、U_id・R を A-b と比べる。

**予想される失敗**

- a が効かず、境界がぼやけて IoU が下がる。
- 物体の中の特徴が一様すぎて、隣も同じように迷っており、票を合わせても決まらない（古典でいう模様のない領域）。この場合は #13（flow の事前情報）を足す理由になる。
- stride 16 の特徴では、頂点の周りの期待値から小数の位置が出ない。
- 並びは直るが、性能は変わらない（反対仮説 (a)）。

#### 学習案：移動ベクトルを少しずつ直す小さなネットワーク（RAFT 型）

**何をするか**

1. 各マスの移動ベクトルを u⁰(p) = 0（動かさない）から始める。
2. 次を K 回くり返す。

   u^{k+1}(p) = u^k(p) ＋ G_θ( s(p, u^k(p) の周り), u^k, 現フレームの特徴 )

   - G_θ は 64×64 の上の小さな畳み込みネットワーク（3×3 の畳み込み数層）。畳み込みなので、隣のマスの類似度と移動を見て直す。隣とそろえる強さを、人が決めずに学習する
   - 類似度の表 s は A-b と同じもの（固定した SAM2 の特徴、窓 225）。新しい特徴抽出器は足さない
3. 行き先 p ＋ u^K(p) の周り4マスから双線形補間で state を持ってきて、Mamba を1歩進める。
4. G_θ の学習は Mamba と分ける。固定した特徴だけで学習でき、SAM2 のデコーダも Mamba も通さない。loss は次の3つ（外部の flow は使わない）。
   - 前フレームの特徴を u で運んだものが、現フレームの特徴と一致する
   - 前フレームの正解マスクを u で運んだものが、現フレームの正解マスクと一致する（今日の「運んだマスクの IoU」を loss にしたもの）
   - u が隣どうしで滑らか
5. G_θ を固定してから、Mamba を A-b と同じ設定で学習する。

**どの弱点を直すか**

- 並：畳み込みが隣を見るので、移動が隣どうしでそろう。制約案と違い、そろえ方（回転・変形のときの崩し方）をデータから決める。
- 小：u が小数なので、1マス未満の動きをそのまま表せる。0 から始めるので、動かない所は動かさないまま。
- 複：1マスに1本の移動ベクトルなので、1マスの state が多数に配られるのは、移動が集まる所（遮蔽・縮小）に限られる。

**設計の選択と根拠**

| 選択 | 値 | 根拠 |
|---|---|---|
| 入力の類似度 | A-b と同じ表（窓 225） | 「潜在空間で対応を取る」を変えない。A-b との差を「選び方」だけにする |
| 表を引く範囲 | u の周り 5×5（最初の1回は窓全体） | RAFT は 1/8 解像度で半径4を多段で引く。こちらは窓が 225 と小さいので多段にしない。5×5 は未確定で、制約案の「1マス以内」に前後1マスの余裕を足した大きさ |
| 反復の回数 K | 1・2・4・8 で比べる | 制約案の T と同じ横軸で、計算量と精度の図に載せる |
| 学習の信号 | 特徴の一致＋正解マスク＋滑らかさ | 性能の loss だけでは信号が弱い（val で 1 pp 未満を判定できない）。マスクの loss は A-b の長所（IoU 0.76）を保つため、滑らかさは内側の並びのため |
| RAFT の flow を教師にするか | 使わない（予備の案） | 使えば内側の並びの信号は強いが、「それなら flow を直接使えばよい」に答えにくくなる |

**最も近い先行研究との違い**

- RAFT：反復で直す形は同じ。違いは、(1) 特徴抽出器を学習せず、固定した SAM2 の stride 16 の特徴の表だけを使う、(2) 出力を画像の flow ではなく Mamba の state の運び先に使う、(3) 教師が flow の正解ではなく、VOS の正解マスクと特徴の一致。
- GRFP・DFF・FGFA：flow で特徴や GRU の state を運ぶ。これらは画像から flow を計算する別のネットワークを使う。
- TrajGRU：state の取得位置を学習する。対応の類似度は使わない。
- TS-Mamba：軌跡を軽量な flow のネットワークで作り、高解像度側の軌跡で教師する（確認した範囲）。state は持ち越さない。
- **新しさは「組み合わせ」で、中くらい。** 個々の部品（RAFT 型の更新、補間で運ぶ、マスクの loss）はどれも既存。

**計算量**：1回あたり、4096 マス × 3×3 の畳み込み数層。64 チャネル・3層なら約4.5億回の積和で、類似度の計算（約2.4億回）の約2倍。K=4 で約8倍（チャネル数・層数は未確定、時間は未計測）。

**学習パラメータ**：あり。数万〜数十万個の見込み（未確定。参考：RAFT small は全体で 1.0M）。

**制約との整合**：SAM2 本体・デコーダには触らない。「Mamba と対応付けの部品だけを学習する」の範囲内。ただし学習が2段になる（G_θ → Mamba）。

**学習なしで比べられるか**：できない。G_θ の学習が要る。ただし固定した特徴だけで学習できるので、Mamba の学習（22 epoch で約 13.5 時間）よりずっと軽い見込み（未計測）。学習後は、今日の3指標でそのまま制約案・A-b・RAFT と並べられる。

**決着がつく最小の実験**：G_θ だけを学習し、制約案と同じ合格条件で判定する。加えて「制約案の最良の設定より、隣とのずれ・折り返しが下がるか」を見る。下がらなければ、学習する意味がないので棄却する。

**予想される失敗**

- 物体の内側は特徴が一様なので、特徴の一致の loss が効かず、滑らかさの loss だけで決まる（移動が0に寄る）。正解マスクの loss は「どの物体か」しか教えないので、内側の並びの信号が足りない。そのときは RAFT の flow を教師に足すかどうかの判断になる。
- 2段の学習で、細かい実装の違いが結果を動かす（観点17）。
- MOSE の学習データに合わせすぎて、SAM2 のゼロショットの良さを損なう。

#### flow 併用案：画像の flow を事前情報として足す

**何をするか**：W(p, d) = softmax_d( s(p, d)/τ − β · ‖d − u_flow(p)‖² )。u_flow は DIS（256×256 で 0.9 ms、CPU）などの flow をマスに平均したもの。β=0 で A-b、β を大きくすると A-a（flow のとおりに運ぶ）になる。

**ねらい**：今日の計測の「A-b は物体を当てる、RAFT は内側の並びを当てる」を、1本の式でつなぐ。先生の 10/30 の見解（実用上は画像の flow を写す方がよい）と、A-a・A-b の公平な比較（観点11）に答える。学習なしで今日の指標で比べられる。パラメータは β の1個。

**弱い点**：主軸の「潜在空間の中で対応を取る」から外れる（11/6：A-b が主体、A-a はできたら）。DIS は速い物体ではみ出し・取りこぼしがある（11/11）。新しさは flow で特徴を運ぶ系（DFF・FGFA・GRFP）に対して小さい。

### 6. 明日（11/13）の MTG の相談文（下書き）

> **相談：①-b の対応付けの直し方を、次の2案のどちらを主軸にするか**
>
> 前回の指摘（類似度が一番高い所に運ぶと、隣のマスがばらばらな所へ行く）を、学習なしで測りました。
>
> - 物体の中で、隣のマスと移動が1マス以上違う組が 33%（RAFT の optical flow では 4%）。隣どうしが交差する折り返しが 17%（RAFT は 2%）。
> - 一方、前フレームのマスクを同じ対応で運ぶと、正解との IoU は 0.76 で、RAFT（0.67）より高い。
> - つまり今の方式は「どの物体から持ってくるか」は当てるが、「物体のどの位置から持ってくるか」は当てていません。
>
> これを直す設計を2つ考えました。実装はまだしていません。先に設計を見ていただきたいです。
>
> **案1（制約を入れる）**：各マスが 15×15 の窓（225マス）の中で類似度から移動先を選ぶとき、上下左右の隣のマスが選んだ移動先と1マス以内でそろう候補の点数を上げ、選び直します。これを数回くり返します。物体の境界（特徴が大きく変わる所）では、そろえません。学習するパラメータはありません。制約を0にすると今の方式と同じになります。
>
> **案2（学習で直す）**：各マスの移動ベクトルを0から始め、同じ類似度を見ながら、小さな畳み込みネットワークで数回直します（optical flow の RAFT と同じ考え方を、SAM2 の潜在空間の 64×64 マスの上で行う）。隣とどれだけそろえるかを、人が決めずに学習します。学習には、前フレームの正解マスクを運んだものが現フレームの正解マスクに合うこと、を使います。
>
> どちらも、SAM2 本体は固定のままで、1マス未満の動きは行き先の周り4マスからの補間で運びます。対応付けは差し替えられる形にし、類似度最大・ハンガリアン・案1・案2・optical flow（DIS、RAFT）を、計算量と上の指標（隣とのずれ、折り返し、運んだマスクの IoU）で1枚の図に並べます。
>
> 聞きたいこと：
>
> 1. 案1と案2のどちらを主軸にするのがよいでしょうか。案1は、すぐに学習なしで良し悪しを判定できますが、考え方は古典的です。案2は学習する部分がありますが、判定までに時間がかかります。私は、案1を先に判定し、足りなければ案2に進む順番を考えています。
> 2. 物体の内側の並びが直ったとして、それが追跡の性能に効くかは、まだ分かっていません。先生は、ここが効くと見ておられますか。

（下書きの注意：「案1・案2」は相談文の中だけの呼び方。手法1・手法2、①・② と混ざらないよう、スライドでは「制約を入れる案」「学習で直す案」と書く方が安全。）
