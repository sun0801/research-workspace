### 高速化の前後比較（`--mode parity`、短い3軌跡、各1回更新）

| 条件 | 1軌跡目のlogit差 | 1軌跡目のloss差 | 勾配の相対差（最大） |
|---|---|---|---|
| FP32：高速化なし同士（再現性の基準） | 0 | 0 | 1.2e-4 |
| FP32：①先読み＋GPUでの正規化＋③待ちの削減 | 0 | 0 | 8.4e-5 |
| FP32：①③＋②まとめ計算 | 5.0e-5 | 3.0e-8 | 4.0e-2 |
| bf16：高速化なし同士 | 0 | 0 | 8.6 |
| bf16：①②③すべて | 0 | 0 | 5.7 |

- 学習のbackwardは、memory-efficient attentionが非決定的なので、同じ条件でも勾配が実行ごとにわずかに変わる（FP32で相対1e-4程度）。2軌跡目以降は更新後の重みが変わるため、forwardもずれていく。
- ①③は、1軌跡目のforwardが完全に一致し、勾配の差も基準と同程度。
- ②（TBPTTの8フレームをまとめて画像エンコーダに通す）は、画像エンコーダの出力が1フレームずつ通した場合と最大9.5e-7（値は最大2.5）異なった。まとめ計算そのものは実行ごとに完全に再現する。原因はバッチの大きさによるGPUの計算方法の違いで、FP32の丸め誤差の範囲と判断した。
- bf16では、高速化ありとなしの差が、高速化なし同士の差と同程度だった。
- 途中で不具合を1つ見つけて直した：GPU上で `div_(255.)` を使うとCUDAが逆数の掛け算に置き換え、CPUの読み込みと1ulpずれていた。tensorで割る形に直し、`mose_fulltrack.load_frame` と全要素一致することを確認した。

## 段階0c checkpointingの正しさ（2026-10-22、A4000、完了）

目的：V3をA4000（16GB）に収めるため、`MambaCell` の1歩をactivation checkpointing（`torch.utils.checkpoint.checkpoint(..., use_reentrant=False)`）で包み、逆伝播のときに途中計算をやり直す形にした（`--adapter-checkpointing`、`TemporalAdapterBase.set_checkpointing()`）。計算結果を変えないことを確かめる。証拠は `runs/mose_temporal_mamba_v3_20261018/stage0c/`。

### 単体（`check_temporal_adapters`、FP32、決定的な設定）：31/31合格

- `MambaCell`（12 step、TBPTT=8、初期stateにも勾配）：オンとオフで出力とconv/SSMのstateは完全一致、パラメータ・入力・初期stateの勾配もノルムに対する差0。初期stateまで時間方向に勾配が届き、detachの境界で次の区間からの勾配が切れることも確認。
- adapter全体（`W_out` とαをゼロでない値に）：V1・V3-64・V3-64-128は12フレーム・TBPTT=8で、出力とstateが完全一致、勾配と1回更新後の重みはノルムに対する差0〜1.2e-7（基準1e-6以下）。V3の3段はオフ側がA4000に収まらないため、4フレーム・TBPTT=2で同じ結果。

### SAM2＋F0に付けた状態

1回目の判定（非決定的な設定、FP32、短い3軌跡、オン／オフ／オフ2回目）：
- V1は合格。V3-64は同じ条件の3回の繰り返しで、合格1回・不合格2回と入れ替わった（不合格は、あるtensorのノルムに対する差が基準（オフ同士の差の2倍）をわずかに超えたもの。例：αの勾配で3.9e-6、基準6.6e-7）。SAM2のattentionのbackwardが非決定的で、基準のオフ同士の差を1回分しか測っていないため、基準自体が不安定だった。V3-64-128以上はオフ側がOOM。
- ユーザーの判断（案A）で、attentionを決定的な計算方法（math backend）にした条件で判定し直すことにした（specに経緯ごと記録）。

決定的な条件での判定（FP32、`--math-attention`、短い3軌跡）：

| 構成 | TBPTT | オフ同士 | オンとオフ：lossとlogit | オンとオフ：勾配・更新後の重み（ノルムに対する差） | VRAMのピーク（オフ → オン） |
|---|---|---|---|---|---|
| V1 | 4 | 完全一致 | 完全一致 | 0 / 0 | 9.72 → 9.74 GiB |
| V3-64 | 4 | 完全一致 | 完全一致 | 0 / 0 | 11.64 → 10.57 GiB |
| V3-64-128 | 4 | 完全一致 | 完全一致 | 0 / 0 | 13.59 → 11.44 GiB |
| V3（3段） | 2 | 完全一致 | 完全一致 | 0 / 0 | 8.84 → 7.12 GiB |

- 全構成で、オンとオフが完全に一致した（基準：ノルムに対する差1e-6以下）。math attentionはメモリを多く使うため、TBPTTを4（3段は2）に短くして確認した。TBPTT=8での一致は単体の確認で確かめている。
- bf16（参考）：math attentionでもbf16ではオフ同士が一致しない（他の演算の非決定性）。V1でオンとオフの差はオフ同士の差と同程度（勾配のノルムに対する差：1軌跡目9.5e-3対7.8e-3、2軌跡目4.5e-2対8.4e-2、3軌跡目0.19対0.71）。V3の3段はbf16・TBPTT=4でOOM。

結論：checkpointingは計算結果を変えない。V3と本学習の設定（`pilot_v3`・`measure_v3`・`train_v3`・`train_v1`）で `adapter_checkpointing: true` にした。

| 軌跡 | フレーム数 | 学習：VRAMのピーク | 学習：秒/フレーム | 推論：VRAMのピーク | 推論：秒/フレーム |
