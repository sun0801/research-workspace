# SAM2MOT再現 CoI除外判定の診断 Spec

## 目的

CoI（A6 のみ）が AssA を下げる経路を特定する。ステップ1（`experiments/2026-10-13-sam2mot-coi-assa-diagnosis.md`）で、AssA 低下の主因は分断ではなく近接する人物間でのトラックの取り違え（出力トラックが複数の人物にまたがる）と分かった。本 spec では、その取り違えが **CoI の除外判定の誤り**（正しく追っていたトラックを誤追跡 B と判定してメモリから外す）によって起きているかを検証する。

結果から、A6（除外判定）を直すべきか、A9（メモリフレーム選択）を直すべきかを決める。本 spec ではハイパーパラメータや A6 の判定そのものは変更しない。

## 背景

- CoI は val・test とも HOTA の寄与が論文に届かない（val +3.90、test +3.6、論文 +5.9）。MOTA の寄与は論文と一致する（val +17.10、test +17.9、論文 +17.7）。不足は AssA の低下（val −1.16、test −2.0）から来ている
- ステップ1の AssA@0.5 分解（TrackEval の `AssA___50` と一致）: S2 → S3 で FPA 他GT +3.11、FNA 他ID +1.38 と損失が増え、FPA 未マッチ −3.12（重複トラックの除去）で相殺される。FNA 未マッチはほぼ不変（−0.18）
- 複数の人物にまたがる出力トラックは 55 → 80 本、乗り移りは 128 → 258 回に増えた。0019 と 0063 では、2本のトラックが2人を数十フレームごとに入れ替える往復が見られる
- 実装（`sam2mot/tracker.py` の `_coi_identify`）: mask IoU > 0.8 のペアを衝突とし、Stage 1 は logit 差 > 2.0 なら **logit の低い方** を B、Stage 2 は直近10フレームの logit 分散の大きい方を B とする。B の現フレームをメモリから外す（A6）
- B 判定は集合にまとめられ、除外はトラックごとにフレームあたり1回だけ行われる（`_cross_object_interaction`）。0026 では B 判定 993 件に対して除外 881 件で、同じフレームで同じトラックが複数ペアの B になっている（3本以上の重なり）
- 衝突判定の対象は `coi_candidates = all_alive` で、出力に box が出ない lost 状態のトラックも含む
- SAM2 は次フレーム（f+1）を推論するとき、keyframe と直近6フレーム（f−5〜f）のマスクメモリに加えて、keyframe と直近15フレーム（f−14〜f）の object pointer を、非 conditioning フレームの記録から集める（`max_obj_ptrs_in_encoder = 16`）。除外されたフレームはどちらからも飛ばされる（古いフレームで補わない）。除外が6フレーム続くとマスクメモリは keyframe だけになるが、f−14〜f−6 の object pointer は残る。15フレーム続くと、object pointer も keyframe だけになる
- 今の出力には CoI の判定イベントが残っておらず、件数しか分からない

## 検証したい問い

1. CoI が B と判定してメモリから外したトラックは、本当に別の人物を追っていた（ずれていた）か
2. 誤除外を含む衝突のあとは、正しく除外された衝突のあとより乗り移りが起きやすいか。同じ衝突の中で A/B の判定が揺れていないか
3. （ステップ3、条件付き）誤除外だけを取り除くと、AssA と HOTA はどれだけ戻るか

## 仮説

- **H1（判定の誤り）**: 別人どうしの衝突で、正しいトラックを B と判定する誤除外が一定の割合で起きており、それが乗り移りの直前に集中している。Stage 1 は logit の低い方を B とするため、隣の人物にしっかり乗ってしまった誤追跡トラックの logit が高いと、正しい方が外される
- **H1b（判定の揺れ）**: 同じ衝突の中で A と B の判定がフレームごとに入れ替わり、2本のトラックが交互にメモリを失う。どちらか一方への誤りというより、判定に一貫性がないことで往復が起きる。誤除外率だけでは見えないので、別の指標で確かめる
- **H2（回復の失敗）**: 判定はおおむね正しいが、外された後のトラックがメモリを失って回復できず、隣の人物へ流れる。除外が続いて、マスクメモリや object pointer が keyframe だけに近づくと起きやすい。この場合は A9（メモリフレーム選択）の問題になる

## 実験・実装内容

### ステップ2: CoI 判定イベントの記録と照合

**実装**（実装リポジトリ `sam2mot_repro/`）

- `_coi_identify` で衝突ペアごとに次を記録する: frame、ペアの2つの track ID、両者の状態（reliable / pending / suspicious / lost）、B と判定した ID（同定しなかった場合はその理由: tie / 履歴不足）、Stage（1 / 2）、両者の logit と差、Stage 2 の場合は両者の分散、mask IoU、両者の box
- `_cross_object_interaction` で、フレームごとに実際にメモリを除外したトラックの集合を記録する（conditioning frame で除外できなかったものを区別する）。これで、ペアの A が別のペアの B として同じフレームで除外されたかが分かる
- 書き出しは新しいフラグ `--coi-event-log <path>`（JSONL）を付けたときだけ行う。既定は OFF
- 判定ロジック・メモリ操作・出力は変更しない。記録は判定の結果を読むだけにする

**実行**

| 項目 | 値 |
|---|---|
| 設定 | S3（A6 のみ）。`s4_run_qr.py --no-qr`、A7 無効（既定）、検出 3x_coco |
| 対象系列 | AssA が大きく下がった 0019、0063、0026 と、上がった 0014、0034（対照） |
| GPU | GPU 0（既存 val run と同じ） |
| 規模 | 既存 run で衝突ペア計 2,348 件（0019: 520、0063: 246、0026: 993、0014: 457、0034: 132）、所要は計 40 分程度 |
| 出力 | `results/tracks/s3_coi_events/`（追跡出力・manifest・イベント JSONL） |

**照合**（読み取り専用の解析。`scripts/diag_coi_assa.py` を拡張するか、別スクリプトにする）

- **トラックの本来の人物**: 衝突フレーム f の直前30フレーム（f−30 〜 f−1）で、そのトラックの出力 box と IoU ≥ 0.5 で最も大きく重なる GT を各フレームで求め、最多の GT をそのトラックの本来の人物とする。マッチしたフレームが10未満なら「判定不能」
- **衝突時点の人物**: フレーム f で、2つのトラックの box と IoU ≥ 0.5 で最も大きく重なる GT。求まらなければ「判定不能」
- 各衝突イベント（フレームごとのペア）を、表の上から順に当てはめて分類する（B = CoI が B と判定したトラック、A = ペアのもう一方）。B が conditioning frame のため除外されなかったイベントは分類から外す（既存 run の5系列では0件）

| 分類 | 条件 |
|---|---|
| 判定不能 | 本来の人物か衝突時点の人物が求まらない。内訳として、lost 状態のトラックを含むものを分ける |
| 重複（無害） | A と B の本来の人物が同じ |
| 両方除外 | A も同じフレームで別のペアの B として除外された（3本以上の重なり） |
| 正しい除外 | B の本来の人物 ≠ 衝突時点の人物、かつ A の本来の人物 = 衝突時点の人物 |
| 誤除外 | A の本来の人物 ≠ 衝突時点の人物、かつ B の本来の人物 = 衝突時点の人物 |
| 両方ずれ | A・B とも本来の人物 ≠ 衝突時点の人物 |

- **別人どうしの衝突** = 正しい除外・誤除外・両方ずれ（A と B の本来の人物がどちらも求まって互いに異なり、A が除外されていないもの）
- **衝突エピソード**: 同じペアの衝突が続くフレームをまとめたもの。間の空きが2フレーム以下ならつなぐ。衝突は連続フレームで続くため、フレーム単位の件数は独立ではなく、長いエピソードが率を左右する。判定はエピソード単位で行い、フレーム単位は参考に出す
- **初回区間**: 2本のトラックのどちらについても、エピソードの開始フレームが、そのトラックの最初の乗り移り（ステップ1と同じ定義）の10フレーム後までにあるもの。乗り移りのないトラックは全区間が初回区間。初回区間では、直前30フレームの窓に乗り移り後のフレームが最大10しか入らないので、本来の人物が安定する。往復区間（0019 の frame 1900〜2100 など）では多数決の人物が10〜20フレームごとに変わり、分類が循環するため、判定は初回区間のエピソードで行い、全エピソードは参考に出す
- **エピソードの分け方**: 別人どうしの衝突エピソードを、誤除外のフレームが過半のもの（誤除外エピソード）と、正しい除外のフレームが過半のもの（正除外エピソード）に分ける（両方ずれのフレームは数えない）。同数のものは分けずに外し、件数を出す。「1フレームでも誤除外があれば誤除外エピソード」とすると、判定が五分五分でも長いエピソードほど誤除外エピソードに入り（10フレームなら 1 − 0.5¹⁰ ≈ 99.9%）、長く接していること自体も乗り移りを起こしやすいので、倍率が長さと交絡する
- **長さの層**: エピソードの衝突フレーム数で、1〜2、3〜9、10以上の3層に分ける
- **判定の揺れ**: エピソード内で、B と判定されたトラックが前の判定フレームから入れ替わった回数。揺れ率 = 入れ替わり回数 ÷（判定フレーム数 − 1）。判定フレームが2未満のエピソードは揺れ率が定義できないので集計から外し、件数を出す
- **メモリの残り**: B が除外されたフレーム f について、f−5〜f（マスクメモリの範囲）と f−14〜f（object pointer の範囲）のそれぞれで、除外されたフレームの数（イベントログから再構成できる。S3 では QR が無効なので、非 conditioning フレームを消すのは CoI だけ）。6 ならマスクメモリ、15 なら object pointer も、次フレームでは keyframe だけになる

### ステップ3（条件付き）: オラクル CoI による介入

ステップ2の結果が「中間」または「H1 支持」のときだけ行う。実施前にあらためてユーザーの承認を得る。

- 診断専用フラグ（例 `--coi-oracle-gt <gt dir>`）を追加し、上の分類で誤除外と判定されるイベントについて、B ではなく A を外す（B と A を入れ替える）。それ以外のイベントは元の判定のままにする
- 本来の人物は、そのフレームより前の自分の出力と GT だけから求める（未来のフレームは使わない）
- 追跡に GT を使うため、**結果は診断専用とし、再現の性能値として報告しない**
- **実装リポジトリの `CLAUDE.md` の例外には当たらない**。`CLAUDE.md` は `gt.txt` を読む経路を作らないことを原則とし、例外を「追跡性能の評価を目的としない計測（プロンプト供給、recall 算出）」に限っている。オラクル CoI は GT で追跡の判定を変え、その結果の HOTA を測るので、この範囲を超える。実施する場合は新しい例外としてユーザーの明示的な承認を得て、`CLAUDE.md` の例外に用途（オラクル CoI、診断専用、性能値として報告しない）を追記してから実装する。フラグ名・出力ディレクトリ名・manifest・experiments にも用途を明記する
- 対象系列はステップ2と同じ5系列

## 使用データ・モデル

- DanceTrack val（GT はステップ2の照合と、ステップ3のオラクル判定にのみ使う）
- 検出 `results/detections/co_dino_l_coco_val25/`（3x_coco）、SAM2.1 large
- 既存出力 `results/tracks/s3_coi_no_lowconf/`（md5 照合の基準）、`results/tracks/s2_addition/`（ステップ3の比較基準）

## 比較対象・ベースライン

- ステップ2: 判定がランダム（どちらを B にするか五分五分）なら、誤除外率（誤除外 ÷（正しい除外 + 誤除外））は 50%
- ステップ2の結びつき: 同じように一方が他方の人物に乗って衝突したが、CoI がおおむね正しく除外したエピソード（正除外エピソード）を、同じ長さの層の中で比べる。衝突で条件付けずに「乗り移りのない時間帯」と比べると、衝突も乗り移りも人が密集したときに起きるため、CoI の判定がランダムでも倍率が大きく出る（近さによる交絡）。この比較は使わない
- ステップ3: 既存の S3（A6 のみ）と S2

## 評価指標

| 指標 | 定義 |
|---|---|
| 主指標1: 誤除外率 | 初回区間の別人どうしの衝突エピソードについて、エピソードごとに 誤除外 ÷（正しい除外 + 誤除外）（フレーム数）を求め、エピソード間で平均した値。両方ずれは分母に入れず、件数と割合を別に出す。Stage 1 / 2 別、logit 差の区間別にも出す |
| 主指標2: 乗り移りとの結びつき（倍率） | 初回区間の別人どうしの衝突エピソードを、多数決で誤除外エピソードと正除外エピソードに分ける。それぞれについて、エピソードの開始から終了後 k = 10 フレームまでに、2本のどちらかが関わる乗り移り（ステップ1と同じ定義、HOTA マッチ・各人物20フレーム以上。関わる = 乗り移ったトラック、または乗り移り先の人物を直前まで追っていたトラック）が起きた割合を求める。長さの層ごとに 誤除外エピソード ÷ 正除外エピソード の倍率と件数を出し、層をまとめた Mantel–Haenszel の倍率（リスク比）を判定に使う。Mantel–Haenszel の分子か分母の合計が0になる場合に限り、各セルに0.5を足して計算し、その旨を明記する |
| 副指標: 判定の揺れ（H1b） | 揺れ率の分布。乗り移りが続いたエピソードと続かなかったエピソード（乗り移りの定義は主指標2と同じ）の平均揺れ率を、長さの層ごとに比べる。揺れ率は判定フレーム数で割っているので主指標2のような偏りは起きないが、長く接していると乗り移りも起きやすいので、長さをそろえて比べる。まとめた値は、層ごとの平均揺れ率を全エピソードの長さの分布で重み付けして平均したもの（直接標準化）とする |
| 副指標: メモリの残り（H2） | 正除外エピソードを、終了後30フレームで B が本来の人物に戻ったもの（B の box と IoU ≥ 0.5 で最も大きく重なる GT が本来の人物であるフレームが過半）と戻らなかったものに分け、エピソード内の「f−5〜f の除外数」と「f−14〜f の除外数」それぞれの最大値を比べる |
| 副指標 | 分類ごとの件数と割合（判定不能は内訳つき）、全エピソードとフレーム単位での主指標1・2、系列別の内訳 |
| ステップ3 | 5系列の HOTA / AssA / IDF1 / MOTA（TrackEval）、ステップ1の AssA 分解、乗り移りの回数 |

## 成功/失敗の判断基準

結果を見る前に固定する。数値は確立した基準ではなく、事後に線を引き直さないための事前登録である。

**実装の合格条件**

- フラグ OFF と ON の両方で、5系列すべての出力が既存の `results/tracks/s3_coi_no_lowconf/` と md5 一致すること。一致しなければ記録処理が判定や出力に影響しているので、先に進まず停止して報告する

**ステップ2の判定**

| 判定 | 条件 | 次の行動 |
|---|---|---|
| H1 支持 | 誤除外率 ≥ 30% **かつ** 倍率 ≥ 2.0 | ステップ3（オラクル CoI）で効果量を確かめ、A6 の判定条件の候補を出す |
| H1 棄却 | 誤除外率 < 15% **または** 倍率 < 1.5 | H2（A9）の方向へ。外された後の回復を調べる計画を立てる |
| 中間 | 上のどちらでもない | ステップ3で判定する |

- 判定は初回区間の別人どうしの衝突エピソードで行う。これが30件未満なら全エピソードで判定し、その旨を明記する。全エピソードでも30件未満なら判定を保留し、対象系列を広げるか相談する
- 多数決で正除外エピソードになったもの（同数で外したものは含まない）が10件未満で主指標2の分母が安定しない場合は、主指標1が H1 支持・棄却の条件に当たっても「中間」とし、ステップ3で判定する
- **H1b**: 乗り移りが続いたエピソードの平均揺れ率（直接標準化）が、続かなかったエピソードの2倍以上なら、上の判定とは別に、A6 の判定に一貫性を持たせる案（ペアごとに B を一定フレーム固定するなど）を候補に加える

**ステップ3の読み方**（TrackEval の AssA。AssA が下がった 0019・0063・0026 の3系列を COMBINED で使う）

- 回復率 =（オラクルの AssA − S3 の AssA）÷（S2 の AssA − S3 の AssA）
- 回復率 ≥ 50% かつ3系列の HOTA が S3 より上がる → 判定の誤りが AssA 低下の主因と判断する。戻った量を、判定を直したときの改善の上限とする
- 回復率 < 20% → 判定以外（H2）の寄与が大きい
- その間 → 判定の誤りは一部の寄与とし、H2 側も調べる
- 対照の 0014・0034 では、オラクルで AssA が S3 より下がらないことを確認する。下がる場合は、オラクルの実装か分類の定義を疑う

## 実施手順

1. 本 spec の承認を得る
2. 実装開始の承認を得る（Implementation Gate: spec のパス、変更範囲 = `sam2mot/tracker.py` の `_coi_identify` と `_cross_object_interaction`、`scripts/s4_run_qr.py` の引数、検証方法 = md5 照合）
3. `--coi-event-log` を実装し、1系列（0026）でフラグ OFF / ON の md5 一致を確認する
4. 5系列を実行し、5系列すべてで md5 一致を確認する
5. 照合スクリプトでイベントを分類してエピソードにまとめ、主指標1・2と副指標を出す
6. 判断基準に照らして判定し、`experiments/` に記録する。実装リポジトリの `logs/` には実行の事実だけを書く
7. 判定が H1 支持または中間なら、ステップ3の実施と、実装リポジトリの `CLAUDE.md` への GT 使用の例外追記をユーザーに確認する

## 期待される結果

- H1 が正しければ、初回区間で誤除外率が 30% 以上あり、とくに Stage 1（logit 差による判定）で多い。誤除外エピソードのあとに乗り移りが起きる割合が、長さをそろえても（Mantel–Haenszel の倍率で）正除外エピソードの2倍以上になる。0019 の frame 1900〜2100 や 0063 の frame 700〜1000 の往復区間（全エピソードの参考集計）でも、誤除外が繰り返されている
- H1b が正しければ、乗り移りが続いたエピソードで A/B の判定が何度も入れ替わっている
- H2 が正しければ、誤除外は少なく、乗り移りの前の除外はほとんどが正しい除外である。正しく除外された B のうち本来の人物に戻らなかったものでは、除外が続いて、マスクメモリ（f−5〜f）に加えて object pointer（f−14〜f）も大きく失われている

## リスク・懸念

- **本来の人物の定義が粗い**: 直前30フレームの多数決は、乗り移りが始まって間もないトラックや往復区間で誤る。判定を初回区間に限ることで抑えるが、30フレームより短い・長い窓（10、60）でも主指標1を出し、結論が変わらないか確認する
- **lost トラック**: 衝突判定には出力に box が出ない lost 状態のトラックも入るので、出力 box から求める本来の人物は判定不能に寄る。判定不能の内訳で lost を含むものを分けて出し、多い場合は明記する
- **衝突時点の人物が曖昧**: 衝突は2つのマスクが重なる状態なので、2人が密着していると box の IoU だけでは人物を決めにくい。判定不能の割合が大きい場合は、その旨を明記する
- **1フレームの除外がどこまで効くか**: 除外は1フレーム単位なので、誤除外が1回あっても乗り移りに直結しない可能性がある。主指標2と副指標（メモリの残り）はその結びつきを確かめるためのものである
- **ステップ3は GT を追跡に使う**: 実装リポジトリの `CLAUDE.md` の例外に当たらないので、承認と例外の追記を実装より先に行う。結果を性能値と混同しないよう、出力ディレクトリ名・manifest・experiments に「オラクル（診断専用）」と明記する
- ログ追加は読むだけの処理にするが、Python 側で numpy 配列を参照・変換するときに状態を変えないよう、md5 照合で担保する
