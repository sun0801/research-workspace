# SAM2MOT再現: 検出器を公式README版（o365tococo）に差し替えた val 25系列 S1〜S4

## 目的

2026-10-09 MTG の方針「まず val を引き上げる」に沿って、検出器 checkpoint を公式 README 記載の Co-DINO-L Objects365→COCO（COCO AP 64.1、以下 o365tococo）に差し替え、現行の 3x_coco（AP 60.0）と val で段別に比較する。spec A8（検出器の適用条件）の切り分けにあたる。

採否基準（2026-10-12、結果を見る前に確定）: **val S4 HOTA が 3x_coco より +1 以上なら主設定を o365tococo に切り替える。**

## 実験条件

## 採否判定

**不採用。** val S4 HOTA の差は +0.05 で、基準の +1 に届かない。主設定は 3x_coco のまま（spec A8 の判断は変更しない）。

## 解釈（暫定）

- **検出器の改善は前段では効くが、CoI・Q-R を足すと消える。** ΔHOTA は S1 +1.31、S2 +1.44 から S3 +0.76、S4 +0.05 へ縮む。o365tococo の強みは FP の減少（S1 −6,087、S2 −3,828）と FN の減少だが、CoI が S2 の FP（主に重複トラック）を大きく削るため、S3 以降は FP がほぼ同水準（約 29,000）になり、検出器による差が残らない。
- **S2 時点の MOTA 差（論文 test より −8.4）は、検出器では説明できない。** S2 の MOTA 改善は +2.09 にとどまる。val と test の split は異なるが、差の大部分は検出器以外（baseline・Object Addition の実装や、検出の後処理条件）に残る。S1 test の提出で baseline 側かどうかを切り分ける余地がある。
- **CoI と Q-R の寄与は、o365tococo ではむしろ小さくなった**（CoI ΔHOTA +3.90 → +3.22、Q-R +1.03 → +0.31）。CoI の寄与不足は検出器の弱さによるものではない。CoI の AssA 低下も o365tococo で −1.16 → −1.83 と同じ向きに残るため、CoI 側の診断（除外判定の正しさ、分断と ID 入れ替わりの分解）は検出器に依存せず進められる。
- 系列間のばらつきが大きいため、COMBINED で ±1 未満の差は、この 25 系列では検出器の効果として判別できない。
