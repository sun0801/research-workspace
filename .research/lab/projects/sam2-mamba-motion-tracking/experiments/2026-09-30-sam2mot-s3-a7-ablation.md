# SAM2MOT再現 S3 切り分け: A7（低信頼フィルタ）を切った run

## 目的

S3 本番 run（`experiments/2026-09-28-sam2mot-s3-coi-results.md`）では、A6（CoI による誤追跡トラックのメモリ除外）と A7（全トラックの低信頼エントリのメモリ除外、logit ≤ 2.0）を同時に有効にしており、AssA −3.21 がどちらによるものか分からなかった。A7 だけを切った run を取り、A6 と A7 の寄与を分ける。

## 実験条件

- S3 本番 run から `--no-coi-low-conf-filter` だけを変えた。コードは S3 本番 run とバイト一致（差分スナップショットと照合済み）
- DanceTrack val 25系列、25/25 成功、形式検証 PASS、所要 2.91 h
- 実行ログは実装リポジトリの `sam2mot_repro/logs/s3_coi_no_lowconf.md`、出力は `results/tracks/s3_coi_no_lowconf/`
- 以下「A6のみ」がこの run、「A6+A7」が S3 本番 run

## 解釈（暫定）

### A7 は association だけを悪化させている

A7 を足すと、HOTA −1.09、AssA −2.05、IDF1 −2.68、IDSW +59 となった。一方、DetA（+0.03）と MOTA（−0.00）はほとんど動かない。AssA は 18 系列で下がった。

A7 を入れると、途中追加が 231 → 320、`lost_tolerance` による削除が 141 → 220 に増える。lost 状態のフレームをメモリから外すと、見失った人物をメモリから再獲得しにくくなり、そのトラックが消えて同じ人物が新規トラックとして追加し直される。この「作り直し」が ID の分断として AssA・IDF1 を下げている、という経路と整合する。ただしトラック単位での確認はしていない。

したがって、S3 本番 run の AssA −3.21 のうち約 −2.05 は A7 によるもの、残りの約 −1.16 が A6 によるもの。A7 の第一候補（τ_s = 2.0 で低信頼フレームを除外）は、今回の実装・val では有害である。

### DetA・MOTA の変化はすべて A6 によるもの

DetA +9.17、MOTA +17.10 は A6 だけで生じ、A7 はそこに寄与していない。S3 本番のメモで整理したとおり、MOTA の改善はほぼ FP の減少によるもので、論文の ΔMOTA +17.7 とも同程度である。spec の機構署名「DetA ほぼ不変」は、この点で論文の数値と両立しにくい（`2026-09-28-sam2mot-s3-coi-results.md` の解釈を参照）。

### A6のみでも、論文との差が残る

- ΔHOTA +3.90 は論文の +5.9 に届かず、Add の +5.11 も下回るので、順序基準は依然として満たさない
- ΔIDF1 +4.29 は論文 +6.5 の約3分の2
- AssA は −1.16 と小さく下がる。混雑系列（0019 −13.77、0063 −11.17、0026 −8.01）で大きく下がり、0014（+6.24）、0034（+6.04）、0077（+5.68）では上がっていて、系列による差が大きい
- 残りの候補は spec の対応表どおり A6（除外範囲、Stage 1 の同定数 6,936）と A9（メモリフレーム選択の最適化が未実装）

## 次の判断（ユーザー決定事項）

1. **A7 の既定を変えるか**: 第一候補（有効、τ_s = 2.0）が有害と分かったので、既定を無効にする案。A1〜A9 の判断を変えるため、spec の A7 行と実装リポジトリの `logs/` に理由を記録する必要がある。変えない場合でも、S4 は A6+A7 の本番設定を前段として進めることになる
2. **spec の機構署名の見直し**: 「DetA ほぼ不変」を、論文の ΔMOTA +17.7 と矛盾しない形（例: IDSW 減・IDF1 増・MOTA 増、DetA は FP 減少で上がりうる）に改める
3. **残る差（HOTA・AssA）の扱い**: A6 の範囲や A9 を探るか、spec の発動条件に従って test 提出で split の差かどうかを確かめるか、差を記録したまま S4 に進むか

## 決定（2026-09-30）

- 1 について、**A7 の既定を無効に変更した**（ユーザー判断）。spec の A7 行と実装リポジトリの `config.py`・`logs/s3_coi_no_lowconf.md` に理由を記録した
- 変更後の既定（フラグなし）の出力が A6のみ run と、`--coi-low-conf-filter` の出力が S3 本番 run と、dancetrack0043 で md5 一致することを確認した
- S4 の前段は A6のみ run（`results/tracks/s3_coi_no_lowconf/`）とする
- S4 実装後に、A7 の有効・無効を再確認する
