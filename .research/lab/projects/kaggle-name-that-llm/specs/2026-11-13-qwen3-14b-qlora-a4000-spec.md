# Qwen3-14B-Base QLoRA を Host142 GPU0（A4000 16GB）で実行する

## 選定の理由

- 誤り分析（primary、基準blend→Spectral後のrecall）: 弱いクラスは `glm-5.3` .31→.33、`claude-fable-5` .30→.37、`glm-5.3-flash` .36→.43、`gemini-3.7-flash` .38→.53、`gpt-5.6-sol/terra` .45→.53/.60、`kimi-k3` .45→.53。いずれも主な誤りは同系列の兄弟モデル（glm-5.3↔flash、gemini-3.7↔3.8-flash、gpt-5.6 luna/sol/terra）。Spectralは多くのクラスを上げるが、glm系・claude-fable-5は基礎信号が弱いまま。系列内の識別を担う新しい基礎成分が要る。
- 同系列向けのCPU補正（pairwise verifier、family-mass rerank、style residual、hierarchical SVC）は実施済みで不採用。同じ型の案は繰り返さない。
- 16GB（使える上限は `max(4 GiB, 25%)` を引いて約12.3 GiB）では、BF16 LoRAの7B（Mistralのpilotで14.5 GiB）は載らない。載るのは4-bit QLoRAの大型モデルだけ。登録済み候補で、QLoRA runner・config・評価script・依存lock・モデルcache（Host142ローカル）が揃うのはQwen3-14B（候補09）のみ。OLMo2-7BはBF16設定で、`gpu_experiment.py`を触らない制約と合わず、別の設計が要る。
- Qwen3-14BはQwen3-8B・1.7Bと同系列だが、16GB・4-bit・official行のみの学習で、既存成分とは条件が違う。多様性は限定的で、Qwen8B/1.7BのSpectral追加は棄却済み（Qwen3-8B .665→+.0007で未確定）。この点は結果の解釈に含める。

## 固定内容

- [候補09のspec](2026-11-08-qwen3-14b-qlora-prompt-grouped-spec.md)の手順（モデル、4-bit NF4、LoRA、学習設定、primary/confirmation分割、固定Sinkhorn後処理、評価・採否ゲート）をそのまま適用する。変えるのは実行先だけ。
- 実行先: Host142 GPU0 `GPU-135ac6e4-8006-058e-ae74-0bb708d0f143`（RTX A4000 16,376 MiB）。configは `configs/gpu17-qwen3-14b-qlora-a4000-prompt-grouped.json`（候補09のconfigから `candidate_id`・`status`・`spec_path`・`resource.gpu_uuid`・`resource.vram_reserve_mib` だけを変更。reserveは16GBの25%＝4,094 MiB）。runner `src/gpu_qwen14b_qlora.py` は変更しない。
- 候補09のGPU1用watcher（停止中、PID 3748103）は再開しない。GPU0用に新しくtmuxで起動する。GPU1はMistral confirmationが使用中で、触らない。
- `max_length 512`・microbatch 2・加算16は変えない。pilotが資源gateを通らない場合は、記録して止める（系列長やbatchを縮めて載せる変更は別の比較なので行わない）。

## 実行手順とゲート

1. 起動直前に `--guard 15`、GPU0の2回のsnapshot（UUID・compute process・空きVRAM）、ホストMemAvailable 16 GiB以上を確認する。他ジョブとの同居はしない。lockは `artifacts/.gpu0-run.lock`。
2. pilot（同じ4-bitモデル・LoRA・系列長・microbatch・optimizer step）。ロス・勾配が有限で、`pilot` の自分の使用量が空きVRAMから4,094 MiBを引いた範囲に収まれば本実行へ進む。全5 foldの所要時間（1 epoch×5）と、4,000行のhidden-test推論時間（T4で8時間以内）の見積もりを記録する。
3. primary全5 fold → 固定additionで基準blendへ1/4加算 → Spectral補正のcomplementarity screen（Mistralと同じ式）。primaryのprompt-paired bootstrap 95%下限が0を超えない場合は、confirmationへ進めない。
4. 本実行はtmuxで切り離し、host・PID・GPU UUID・ログ・resume位置を実験ログに記録する。
