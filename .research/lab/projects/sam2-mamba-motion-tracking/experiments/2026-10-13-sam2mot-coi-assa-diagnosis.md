# SAM2MOT再現 CoI診断 ステップ1: AssA 低下の中身を既存出力と GT で分解する

## 目的

CoI（A6 のみ）は val・test とも AssA を下げ（val −1.16 / test −2.0）、HOTA・IDF1 の寄与が論文に届かない。AssA の低下が

- **分断**（トラックが消え、同じ人物に新しい ID が作り直される）
- **人物の取り違え**（トラックが別の人物に乗り移る、2本のトラックが人物を入れ替える）

のどちらによるかを、既存の S2・S3 出力と GT だけで切り分ける。コードと出力は変更していない（読み取り専用の解析）。

計画は brainstorm `2026-10-12-sam2mot-val-improvement-plan.md` の B。o365tococo の比較（`2026-10-13-sam2mot-o365tococo-val.md`）で、CoI の AssA 低下は検出器に依存しないことを確認済み。

## 方法

| 項目 | 値 |
|---|---|
| 対象 | S2 `results/tracks/s2_addition`、S3（A6 のみ）`results/tracks/s3_coi_no_lowconf`。検出器は 3x_coco |
| スクリプト | 実装リポジトリ `sam2mot_repro/scripts/diag_coi_assa.py`（新規。既存コードは未変更） |
| 出力 | `results/diag/coi_assa/s2_s3.json`（GT 軌跡ごとの切り替わりイベントを含む）、`s2_s3.md`（表） |
| GT の用途 | この解析のためだけに参照する。追跡の入力には使っていない |

### AssA の損失分解

HOTA の AssA は、TP 1件ごとの `TPA / (TPA + FNA + FPA)` の平均である。1 − AssA を次の4つの取り分に分けた。

| 取り分 | 意味 |
|---|---|
| FNA 他ID | GT 人物 g のフレームのうち、別の出力 ID に追われていた分（g が複数の ID に分かれる） |
| FNA 未マッチ | g のフレームのうち、どの出力にも追われていなかった分 |
| FPA 他GT | 出力トラック p のフレームのうち、別の人物にマッチしていた分（p が複数の人物にまたがる） |
| FPA 未マッチ | p のフレームのうち、どの人物にもマッチしていなかった分（重複トラック・背景など） |

マッチは TrackEval HOTA と同じ手順（global alignment score × IoU で Hungarian、α = 0.5 で採用）を再実装した。**AssA@0.5 は TrackEval の `AssA___50` と小数第4位まで一致**した（例: 0019 S2 0.6071 / S3 0.4677、COMBINED S2 0.7039 / S3 0.6919）。TrackEval の AssA（AUC）は α の平均なので値は一致しないが、COMBINED の低下は α によらずほぼ一定（−0.9〜−1.4）なので、α = 0.5 の分解で代表させた。

最初に CLEAR MOT 型のマッチ（IoU ≥ 0.5、前フレームの組を優先）で切り替わりを数えたが、そのマッチで計算した AssA は 0019 で S2 → S3 に上がり、TrackEval と逆向きになった。HOTA は global alignment score でマッチを選ぶため、どのトラックがどの人物に対応するかが CLEAR と変わる。AssA の議論には HOTA のマッチを使う。

### 人物をまたぐ出力トラック（HOTA マッチ、α = 0.5、25系列合計）

各人物に 20 フレーム以上マッチした出力トラックを「複数人物にまたがるトラック」、その中で人物が変わる点を「乗り移り」とした。

| | 複数人物にまたがるトラック | 乗り移り | うち、乗り移り先の人物を直前まで追っていたトラックが30フレーム以内に終了 |
|---|---|---|---|
| S2 | 55 | 128 | 12 |
| S3 | 80 | 258 | 35 |

AssA が大きく下がった系列の S3 での例（`g` は GT の人物 ID、括弧はフレーム範囲）:

- **0019 の往復**: トラック 8 と 11 が、frame 1900〜2100 の間、人物 g1 と g4 を約10〜20フレームごとに入れ替えて追う（8: g1 → g4 → g1 → g4 …、11 はその逆）。S2 ではこの区間で同様の往復は起きていない
- **0019 の3人ローテーション**: frame 770〜830 で、トラック 7 が g4 → g3、6 が g3 → g2、4 が g2 → g4 に乗り移り、3人の ID が一巡する
- **0063 の往復**: トラック 1 と 9 が frame 700〜1000 の間、人物 g6 と g7 を入れ替え続ける。S2 では複数人物にまたがるトラックが 0 本

### 参考: CLEAR 型マッチでの切り替わり分類（25系列合計）

| | 切り替わり | 作り直し（消えて新 ID） | 入れ替わり（既存同士） | 流れ出し | 乗っ取り | 早期終了 |
|---|---|---|---|---|---|---|
| S2 | 977 | 26 | 788 | 133 | 30 | 22 |
| S3 | 755 | 52 | 564 | 90 | 49 | 44 |

切り替わりの総数は TrackEval の IDSW と同じ桁（S2 1,162 / S3 839）。CoI は S2 の重複トラック間の入れ替わりを減らす一方、作り直し（26 → 52）と早期終了（22 → 44）は倍増している。ただし件数は小さい。

## 解釈（暫定）

- **CoI の AssA 低下の主因は、分断ではなく人物の取り違え**。FNA 未マッチはほぼ不変で、増えた損失は「出力トラックが複数の人物にまたがる」（FPA 他GT +3.11）と「人物が複数の ID に分かれる」（FNA 他ID +1.38）。乗り移りは S2 の 128 から S3 の 258 に倍増した。トラックが消えて作り直される経路（作り直し・早期終了の倍増）もあるが、件数は少なく、損失の取り分としても小さい
- **取り違えは、近接して動く2〜3人の間での往復・ローテーション**として起きている（0019、0063）。S2 では同じ区間で起きていないので、CoI のメモリ除外がきっかけになっていると考えられる（hypothesis）
- 想定される経路: 2本のトラックが同じ人物に重なって衝突したとき、CoI が**正しく追っていた方**を誤追跡 B と判定してメモリから外すと、そのトラックはメモリを失って隣の人物へ流れ、もう一方がその人物を引き継ぐ。これが繰り返されると往復になる（hypothesis）。これは Stage 1（logit 差 > 2.0）の判定が、隣の人物にしっかり乗った誤追跡トラックの方を高く評価してしまう場合に起きる
- CoI は全体として重複トラックを消して FP を大きく減らしており（MOTA +17.1）、その効果は残したまま、判定の誤りだけを減らせるかが論点になる

## 次（ステップ2の候補）

上の経路を確かめるには、CoI が**どのフレームで、どのペアを、どちらを B と判定したか**の記録が必要。今の出力には件数しか残っていない。

- ランナーに CoI イベント（frame、A・B の ID、Stage 1/2 の別、両者の logit）を JSONL に書き出すフラグを追加する。出力は変えないので、フラグ ON/OFF で出力の md5 一致を確認する
- 0019・0063・0026 など AssA が大きく下がった系列だけを再実行し、イベントを GT と突き合わせて**除外の正解率**（外した B が本当に別人を追っていたか）を出す。とくに上の往復区間で、正しいトラックが B と判定されていたかを見る
- 結果に応じて、A6 の判定（Stage 2 を必須にする、logit 差の閾値、衝突の連続フレーム数の条件など）または A9（メモリフレームの選び方）の候補を spec に追記する

ステップ2は実装リポジトリのコードに手を入れるため、着手前にユーザーの承認を得る。
